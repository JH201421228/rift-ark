AI는 기획 정리, 코드 구현, 테스트 설계, 밸런스 분석, 이미지 제작 보조와 출시 문서 작성에 사용했습니다. 최종 규칙의 결정과 배포 승인 책임은 개발자에게 있으며, 게임 실행 중에는 LLM·이미지 생성 API를 호출하지 않습니다.

사람과 AI의 책임 경계

1. 사람의 의도게임 훅, 범위, 수익화, 난이도와 출시 판단을 결정
2. 제약 입력정본 데이터·금지사항·소유 파일·완료 조건을 프롬프트에 명시
3. AI 작업구현·문서·에셋 후보·검사기를 작은 단위로 생성
4. 증거 검증테스트·시뮬레이션·실행 캡처·사람의 시각 검수로 채택

AI가 결정하지 않은 것

  • 무료/유료와 광고 도입 여부
  • 게임의 핵심 조작과 편성 중심 철학
  • 밸런스 게이트 실패를 허용할지의 최종 판정
  • 외부 에셋 사용 권한에 대한 오너 확인
  • 스토어 제출·계정·법무 응답

런타임에서 AI를 쓰지 않는 이유

  • 전투 결과의 재현성과 오프라인 플레이 보장
  • 응답 지연·비용·네트워크 장애 제거
  • 심사 시 동일 입력에 동일 규칙 적용
  • 개인정보를 외부 AI 서비스로 전송하지 않음

PROMPT DESIGN

주요 프롬프트와 지시 방식

02 / 06

아래는 실제 작업 지시를 심사용으로 축약·정규화한 발췌입니다. 전문은 CLAUDE.md, docs/05-art-briefs/40, docs/06-release/52·54에 남아 있습니다.

1) 코드 구현·수정

[TASK] 해당 기능을 구현하라. 먼저 CLAUDE.md와 관련 설계 문서를 읽고 정본 JSON에서 수치를 가져온다. src/game/logic은 DOM·React·Phaser에 의존하지 않는 순수 규칙으로 유지한다. 프레임 루프에서 배열·문자열·객체를 생성하지 말고 반복 객체는 풀링한다. 기존 테스트를 보존하고 경계·실패 경로 테스트를 추가한다. 완료 전 lint, test, data:validate 및 관련 검사기를 실행하고 미완료를 보고한다.

2) 밸런스 분석

고정 시드 시뮬레이션으로 변경 전·후를 비교하라. 승률 하나만 보지 말고 도달 가능성, 골드 여유, 편성 다양성, 별 조건을 함께 기록한다. 실패한 게이트를 임의로 완화하지 말고 원인이 규칙·데이터·하네스 중 어디인지 분리한다. 밸런스 수치는 코드에 박지 말고 JSON 한 곳에 두며 하네스도 같은 값을 읽게 한다.

3) 이미지 생성

[STYLE — RIFT ARK] 가로형 모바일 레인 디펜스용 현대적 HD 픽셀아트. 배경 #0f0f1e, 금색 #F2B33D, 균열 보라 #B45AD6. 안티앨리어싱 없이 단단한 픽셀 덩어리와 디더링을 사용한다. 요청한 레이어/구조물 하나만 만들고 텍스트·UI·로고·기기 프레임을 그리지 않는다. 기존 유명 게임의 캐릭터·로고·고유 실루엣을 모방하지 않는다.

4) 스토어 스크린샷

스크린샷 본체를 생성하지 말고 dev 빌드의 실제 실행 화면을 캡처한다. 고정된 8개 장면과 상태 주입 손잡이를 사용하고 FPS·디버그 UI를 숨긴다. 한국어와 영어는 같은 장면을 사용하며 카피는 store-copy.json 한 곳에서 읽는다. Play 1920×1080, iOS 2868×1320, sRGB·불투명·용량을 자동 검사한다. 검사기에 금지 카피를 일부러 넣어 non-zero 실패를 확인한 뒤 원복한다.
핵심 원칙: AI가 장르 상식으로 빈칸을 채우지 못하게 사실·수치·금지 목록을 프롬프트에 함께 넣었습니다. “없는 기능을 그럴듯하게 추가하는 것”을 가장 위험한 실패로 취급했습니다.

AI 결과를 그대로 믿지 않기 위한 장치

단일 출처(SSOT)

밸런스·텍스트·출처를 JSON 한 곳에 두고 화면·시뮬레이터·문서 생성기가 같은 값을 읽습니다.

검사기 파괴 시험

새 검사기는 금지 값이나 잘못된 카피를 일부러 넣어 실제로 실패하는지 확인한 뒤 원복합니다.

실행 화면 우선

테스트가 통과해도 UI는 실제 뷰포트에서 열어 확인합니다. 스토어 화면은 AI 목업을 폐기하고 런타임 캡처로 교체했습니다.

불확실성 기록

실기기·스토어 콘솔처럼 로컬에서 확인할 수 없는 항목은 추정으로 숨기지 않고 출시 문서의 미결 목록에 남깁니다.
