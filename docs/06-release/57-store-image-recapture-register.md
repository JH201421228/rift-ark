> → `check-store-shots.mjs` 에 **`checkFreshness()`** 를 넣었다:
> `store-copy.json` 이 `raw/*.png` 보다 새로우면 실패한다.
> `check-production.mjs` 의 **D1**("dist 가 소스보다 오래됐다")과 같은 규칙이다 —
> **검사 대상이 낡으면 통과는 거짓말이다.**

## 1. S-01 — 1번 장면에 공중 적이 없다 ✅ **완료 (2026-08-08)**

> ### 선택지 ②를 골랐다 — **스테이지 데이터를 고치지 않는다**
>
> 아래 §1 의 두 선택지 중 **②(다른 실제 스테이지로 옮긴다)** 를 택했다.
> 스크린샷 한 장 때문에 `balance:check` · `economy` · `playthrough` 를 통과한
> 캠페인 데이터를 흔들 이유가 없다.
>
> `SCENES[0].route` = **`#/battle/2-8`**. `2-4` 와 **같은 월드 2 · 같은 goblin
> 진영 · 같은 assault 모드 · 같은 18 웨이브**인데 FLYING 적이 웨이브 1부터 총
> 43마리 나온다. 화면 톤은 그대로 두고 하늘만 채워진다.
>
> | 완료 조건 | 결과 |
> |---|---|
> | 캡처 로그의 `airEnemies >= 1` | ✅ **5~6** (ko·en · play·ios 전부) |
> | 아군 하늘색 타원과 적 붉은 링 구분 | ✅ 눈으로 확인 |
> | 한국어·영어 검사기 통과 | ✅ |
> | **교전 중인 지상 레인 3개** | ⚠ **2 다 — 채우지 못했다** |
>
> **`engagedGround` 2 를 그대로 둔 이유:** 후보를 3 → 5 로 늘려도 전부 2 였다.
> 후보 간격이 1.8초뿐이라 5개가 같은 국면(웨이브 4의 8초 안)에 몰리기 때문이고,
> 병목은 표본 수가 아니라 **시간 폭**이다. 그리고 이것은 트레이드오프다 —
> 같은 날 가드 시험으로 `2-4` 를 다시 찍었을 때 그쪽은 `engagedGround: 3` ·
> `airEnemies: 0` 이었다. **공중 적이 지상 교전을 분산시킨다.**
> 카피(`세 개의 레인과 하늘`)가 약속하는 것은 **하늘**이므로 이쪽을 골랐다.
> 세 레인 모두에 병력은 서 있다.
>
> ### ★★★ 그리고 기계가 잡게 만들었다
>
> `battleScore` 는 **처음부터** `airEnemies` 에 가점을 주고 있었다. 그런데도 4개월
> 동안 0 이었다 — **데이터에 없는 것을 점수가 만들어 낼 수는 없고, 가점은
> 강제가 아니다.** 지상 교전 점수만으로 0마리 후보가 1위가 될 수 있다.
> 그리고 `check-store-shots.mjs` 는 픽셀 속 적을 셀 수 없다.
>
> → `captureBattleMid` 가 최종 후보의 `airEnemies` 가 0 이면 **저장하지 않고
> 던진다.** 경고만 하고 저장하면 그 그림이 그대로 스토어에 올라간다.
> 가드는 `2-4` 로 되돌려 실제로 깨뜨려 확인했다.

### (2026-08-07 기록) 원래 문제

### 증거

`capture-store-shots.mjs` 의 2026-08-07 실제 캡처 로그에서 한국어·영어, Play·iOS
후보가 모두 `airEnemies: 0` 이었다. 화면은 세 지상 레인의 교전을 보여 주지만,
`52 §3.2` 가 요구한 **공중 적 존재**는 보여 주지 못한다.

카피도 공중 전투를 직접 약속한다.

- 한국어: `세 개의 레인과 하늘. 하나도 뚫리면 안 된다`
- 영어: `Three lanes and the sky. Hold them all.`

### 촬영 전에 먼저 결정할 것

아래 둘 중 하나가 정해지기 전에는 그림 편집이나 가짜 적 주입으로 고치지 않는다.

1. 고정 장면 `#/battle/2-4` 의 실제 웨이브에 공중 적을 넣는다.

캡처 전용으로 존재하지 않는 적을 합성하거나 전투 상태에 강제로 끼워 넣으면 실제
플레이 화면이라는 보장이 깨진다.

## 3. S-03 — 광고 활성화 릴리스에서 8번을 다시 찍는다 ✅ **완료 (2026-08-08)**

> **트리거가 발동했다** — `ads.json:enabled` 를 `true` 로 켜고 실제 AdMob 앱 ID·
> 광고 단위 ID 를 넣었다. 실제로 찍힌 카피:
>
> - 한국어: `확률형 없음 · 인앱결제 없음 · 광고는 선택`
> - 영어: `100 stages. No IAP. No gacha. Ads are optional.`
>
> ★ 아래 "현재는 왜 유효한가" 는 **2026-08-07 시점의 기록**이다. 지금은 성립하지 않는다.

### (2026-08-07 기록) 현재는 왜 유효한가

`FE/src/game/data/ads.json` 의 현재 값은 `enabled: false` 이고 실제 광고 단위 ID도
비어 있다. 따라서 현재 1.0 이미지의 다음 문구는 사실이다.

- 한국어: `확률형 없음 · 광고 없음 · 인앱결제 없음 · 오프라인`
- 영어: `100 stages. No ads. No IAP. No gacha.`

### 재촬영 트리거

다음 중 하나라도 일어나면 **광고가 포함된 빌드를 스토어에 제출하기 전에** 8번을
다시 찍는다.

- `ads.json:enabled` 를 `true` 로 바꾼다.
- 실제 AdMob 광고 단위 ID를 넣고 광고 포함 릴리스를 준비한다.
- Play Console의 광고 항목을 `예`로 바꾸거나 Apple 심사 메타데이터에 광고를 신고한다.

### 교체 카피

`FE/tools/store-copy.json` 8번에서 광고 부재 주장만 제거한다.

```text
ko: 100 스테이지 · 확률형 없음 · 인앱결제 없음
en: 100 stages. No IAP. No gacha.
```

최종 문구는 광고 활성화 직전 `56 §4.1` 과 함께 다시 대조한다.

### 영향받는 파일

| 언어 | 원본 | 최종본 |
|---|---|---|
| 한국어 | `raw/play-8.png` · `raw/ios-69-8.png` | `play/play-screenshot-8.png` · `ios/ios-69-8.png` |
| 영어 | `en/raw/play-8.png` · `en/raw/ios-69-8.png` | `en/play/play-screenshot-8.png` · `en/ios/ios-69-8.png` |

광고 SDK 설치 여부만으로 즉시 재촬영하지 않는다. 사용자에게 실제로 광고가 노출되는
릴리스인지가 기준이다. 다만 `56 §8` 의 권장처럼 처음부터 광고 부재 문구를 쓰지 않기로
정책을 바꾸면 활성화 전이라도 S-03을 앞당긴다.

## 4. 재촬영 절차

### 4.1 시작 전

1. 바꿀 카피는 `FE/tools/store-copy.json` 한 곳만 수정한다.
2. 기존 원본과 최종본은 `store/_recapture-backup/<날짜>/` 로 복사해 둔다.

   > ★ **그 폴더는 `.gitignore` 대상이다** (2026-08-08). 로컬 안전망일 뿐이고,
   > **이전 판의 권위는 git 히스토리**다 — `store/raw/` 가 추적되고 있으므로
   > `git show <커밋>:FE/asset/generated/store/raw/play-8.png > 어딘가.png` 로
   > 언제든 꺼낼 수 있다. 한 세트가 39MB 라 커밋하면 그대로 히스토리에 남는다.
3. `5173` 은 사용자의 개발 서버이므로 사용하지 않는다. 캡처 도구는 `5199`, CDP는
   `9333` 을 쓴다.

### 4.2 실행

현재 도구에는 장면 하나만 찍는 `--scene` 옵션이 없다. 안전한 기본 절차는 언어별
16장을 전부 다시 찍는 것이다.

```powershell
cd FE
npm run store:capture
npm run store:compose
npm run store:check

npm run store:capture:en
npm run store:compose:en
npm run store:check:en
```

`--resume` 은 기존 원본을 그대로 유지하므로 재촬영할 번호의 원본을 백업 폴더로 옮긴
뒤에만 사용한다. 그렇지 않으면 문제 있는 원본을 성공한 것으로 보고 건너뛴다.

### 4.3 끝난 뒤

- 금지 카피를 일부러 한 번 넣어 검사기가 0이 아닌 코드로 실패하는지 확인하고 원복한다.
- Play와 iOS 결과를 각각 눈으로 본다.
- `5199` · `9333` 포트와 Chrome · Vite 프로세스가 남지 않았는지 확인한다.
- 이 문서의 해당 ID를 완료로 바꾸고 촬영일과 변경 근거를 남긴다.
