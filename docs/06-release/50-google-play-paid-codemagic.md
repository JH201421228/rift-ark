## ⚠ 먼저 읽을 것 — 이 문서의 유효기간

**스토어 정책은 이 문서보다 빨리 바뀐다.** 아래 항목은 **반드시 콘솔 화면에서 직접
확인**한다. 화면이 이 문서와 다르면 **화면이 맞다.**

| 확인할 것 | 어디서 |
|---|---|
| target API 레벨 요구치 (매년 8월 말 상향) | ✅ **2026-08-08 대응: `targetSdk 36`**(Android 16). `src/androidTarget.test.js` 가 붙잡는다 — 다음 상향 때 그 검사도 함께 올린다 |
| 개인 계정의 클로즈드 테스트 요구 (인원 · 일수) | Play Console → 대시보드 → 프로덕션 액세스 |
| **데이터 보안 · 광고 ID · 광고 포함 선언의 문항 문구** | Play Console → 정책 → 앱 콘텐츠 |
| **AdMob 지급 기준액 · 지급일 · 세금 양식** | AdMob → 지급 |
| 신원 확인에 필요한 서류 | 계정 생성 마지막 단계 |

**나는 세무사도 변호사도 아니다.** §8(세금)은 "무엇을 알아봐야 하는지"의 목록이지
답이 아니다. 광고 수익이 붙으면서 **소득의 성격 자체가 앱 판매에서 광고 수익으로
바뀌었다** — 예전 문장을 그대로 쓰면 안 된다 (§8.3).

### 1.1 Git 저장소 ✅ **완료** (2026-08-07)

**Codemagic 은 Git 원격에서만 빌드한다.**

| | |
|---|---|
| 원격 | `github.com/JH201421228/rift-ark` (**private**) |
| 브랜치 | `main` · `stage` · **`dev`**(통합) |
| 작업 규약 | `dev` 아래 브랜치를 파서 작업 → 커밋 → 푸시 → `dev` 에 `--no-ff` 머지 |

> ★ **CI 가 어느 브랜치를 볼지 정해야 한다.** `dev` 는 통합 브랜치라 자주 깨질 수
> 있으므로, Codemagic 의 릴리스 워크플로는 **`main`**(또는 태그)에 붙이고
> `dev` 에는 검증 워크플로만 거는 편이 안전하다 (§6).

> **private 로 만든다.** 에셋 라이선스는 자유 사용이지만 소스를 공개할 이유가 없고,
> 광고를 붙이면 **AdMob 광고 단위 ID 와 앱 ID 가 저장소에 들어간다** (`56 §2.3`).
> 그것들은 비밀은 아니지만 공개 저장소에 두면 남이 자기 앱에 붙여 무효 트래픽을
> 만들 수 있다. Codemagic 은 private 저장소를 정상 지원한다.

#### 실행 (사용자 터미널에서 직접)

**한 줄로 붙여넣는다.**

```bash
keytool -genkeypair -v -keystore C:/keys/riftark-release.jks -alias riftark -keyalg RSA -keysize 4096 -validity 10000 -storetype PKCS12 -dname "CN=Rift Ark, OU=Development, O=Rift Ark, L=Seoul, ST=Seoul, C=KR"
```

물어보는 것은 **비밀번호 두 번뿐**이다.

| 질문 | 무엇을 넣나 |
|---|---|
| Enter keystore password | **ASCII 만.** 20자 이상 권장. **반드시 기록** |
| Re-enter new password | 같은 값 |

> ### ★★★ 비밀번호는 **ASCII 만** 된다 — 2026-08-08 에 실제로 여기서 막혔다
>
> ```
> keytool error: java.security.KeyStoreException: Key protection algorithm not found:
>   java.security.UnrecoverableKeyException: Encrypt Private Key failed:
>   getSecretKey failed: Password is not ASCII
> ```
>
> Java 의 PKCS12 구현(`com.sun.crypto.provider.PBEKey`)은 비밀번호의 **모든 문자가
> 0x80 미만**이어야 한다. 한글이 한 글자라도 섞이면 — 대개 **한/영 키가 한글에
> 놓인 채로 입력해서** — 위 예외가 난다.
>
> **이 오류가 위험한 이유는 메시지가 스택 트레이스이기 때문이다.** 진짜 원인
> (`Password is not ASCII`)은 40줄짜리 트레이스의 **맨 아래**에 한 번 나오고,
> 맨 위 줄은 "Key protection algorithm not found" 라고 말한다 — 알고리즘 문제로
> 읽혀서 `-keyalg` 를 의심하게 만든다.
>
> ★ **파일은 남지 않는다.** 실패는 키를 저장소에 넣는 마지막 단계에서 나므로
> 잔재를 지울 필요 없이 그대로 다시 실행하면 된다. (`C:\keys\` 가 비어 있는지
> 확인하고 시작하면 확실하다.)
>

### 1.3 `build.gradle` 서명 설정 ✅ **완료** (2026-08-08)

> ### ★★ 정본은 코드다 — 여기에 스니펫을 복사해 두지 않는다
>
> **`FE/android/app/build.gradle`** 이 유일한 출처다. 예전에는 이 자리에 전체
> 스니펫이 붙어 있었고, 실제 파일이 앞서 나가면서 **문서의 스니펫이 이미 세 군데

> **아래는 그 파일이 왜 그렇게 생겼는지만 적는다.**

`FE/android/app/build.gradle` 은 자격증명을 **두 곳**에서 받는다 —
CI 는 Codemagic 의 `CM_*` 환경변수, 로컬은 `key.properties`.

| 결정 | 왜 |
|---|---|
| 자격증명이 **하나도 없으면 서명을 배선하지 않는다** (`canSignRelease`) | 무조건 `signingConfig` 를 걸면 **키 없는 환경의 `assembleDebug` 까지 설정 단계에서 죽는다.** 클론 직후 첫 빌드가 `storeFile is null` 로 실패하면 안 된다 — 서명이 필요한 것은 `bundleRelease` 뿐이다 |
| `versionCode` = **`VERSION_CODE_BASE` + `BUILD_NUMBER`** | ★★★ 아래 절 |
| `BUILD_NUMBER`·`VERSION_CODE_BASE` 가 정수가 아니면 **빌드를 멈춘다** | 조용히 떨어지면 이미 쓴 번호가 다시 나오고, 원인이 환경변수라는 것을 알기까지 한참 걸린다 |
| 합이 1 미만이면 **빌드를 멈춘다** | Play 가 거부하는 값을 만들어 놓고 성공으로 끝내지 않는다 |
| `keyPassword` 가 비면 `storePassword` 로 폴백 | PKCS12 는 저장소 비밀번호 하나가 키까지 보호한다. 둘을 다르게 적는 실수가 "키를 못 연다"로 나타나는 것을 막는다 |
| `minifyEnabled false` 유지 | Phaser 는 씬·플러그인을 **문자열 이름**으로 찾고 Capacitor 플러그인은 리플렉션으로 불린다. R8 이 지우면 **빌드는 성공하고 실행이 죽는다** (§1.4 크기 표의 원인이기도 하다) |

#### ★★★ `versionCode` — CI 와 로컬은 **번호 공간을 나눠 쓴다** (2026-08-08)

**한 번 올린 `versionCode` 는 영원히 재사용할 수 없다.** 앱에서 지워도, 초안이어도 같다.

그리고 **Codemagic 의 `BUILD_NUMBER` 는 그 앱의 첫 빌드에서 1부터 시작한다.**
그래서 손으로 1·2 를 올린 뒤 CI 를 붙이면 **첫 자동 빌드가 그대로 거부된다.**

> 실제로 겪었다 (2026-08-08): *"1 버전 코드는 이미 사용되었습니다."*

| 어디 | 값 | 범위 |
|---|---|---|
| **CI** | `VERSION_CODE_BASE`(1000) + `BUILD_NUMBER` | **1001 부터** |
| **로컬 수동** | `BUILD_NUMBER` (오프셋 없음) | **1000 미만** |
| 로컬 기본 (환경변수 없음) | `1` | 디버그·개발용 |

두 공간이 겹치지 않으므로 어느 쪽을 몇 번 돌려도 충돌하지 않는다.

```bash
# 손으로 올릴 AAB 를 만들 때 — 다음 번호를 직접 준다
cd FE/android && BUILD_NUMBER=3 ./gradlew bundleRelease
```

> ★ **CI 인지 코드가 추측하지 않는다.** `CM_BUILD_ID` 나 `CI` 같은 변수를 보고
> 분기하면 그 이름이 바뀌는 날 오프셋이 **조용히 0** 이 되고 충돌이 돌아온다.
> 오프셋은 `codemagic.yaml` 의 `vars` 에 적힌 값이라 **코드 리뷰에 보인다.**
>
> ★ **Codemagic 콘솔의 "빌드 번호 시작값"으로 대신하지 않는다.** 콘솔 설정은
> 저장소를 아무리 봐도 알 수 없고, Codemagic 앱을 다시 만들면 조용히 1 로 돌아간다.
>
> ★ CI 검증 스텝이 **`versionCode > 1000`** 을 따로 본다 — 오프셋이 전달되지
> 않으면 빌드 단계에서 멈춘다. 그러지 않으면 실패가 **업로드에서** 나고, 그건 한참 뒤다.

메시지에는 **OOM 이라는 단어가 한 번도 나오지 않고**, 데몬이 죽었으니 Gradle 쪽

**그 방향이 틀렸다. 올리면 오히려 나빠진다.**

진짜 원인은 `FE/android/hs_err_pid*.log` **맨 위 세 줄**에 있다:

```
Native memory allocation (malloc) failed to allocate 1187056 bytes for Chunk::new
  The system is out of physical RAM or swap space
```

**힙(`-Xmx`)이 아니라 시스템 커밋 한도가 바닥나 있었다.** 실측 당시:

| | |
|---|---|
| 물리 메모리 | 15.7GB (여유 **2.6GB**) |
| 총 커밋 한도 (물리 + 페이지파일) | 64.9GB (여유 **3.6GB**) |
| ★ 범인 | **21시간 돌던 `npm run dev` 의 Vite 프로세스 하나가 커밋 48GB** |

Vite 의 작업 세트(working set)는 1.5GB 밖에 안 돼서 **작업 관리자에서는 정상으로
보인다.** 커밋 차지를 봐야 보인다.

**증상이 나오면 `gradle.properties` 를 만지기 전에 이것부터 본다:**

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object FreePhysicalMemory, FreeVirtualMemory
Get-Process | Sort-Object PrivateMemorySize64 -Descending |
  Select-Object -First 5 ProcessName, @{n='Commit_MB';e={[int]($_.PrivateMemorySize64/1MB)}}
```

`FreeVirtualMemory` 가 몇 GB 뿐이면 **범인은 Gradle 이 아니라 다른 프로세스다.**

> ★ **`-Xmx` 를 올리는 것이 이 증상을 악화시키는 이유:** 힙은 JVM 이 미리 커밋하는
> 양이다. 커밋이 부족한 상태에서 키우면 C2 컴파일러 arena 같은 **네이티브** 할당이
> 쓸 몫이 오히려 줄어든다. 로그의 실패 지점이 정확히 거기였다 (`C2 CompilerThread1`).
>
> ★ **AAB 빌드 전에는 개발 서버를 끈다.** `bundleRelease` 는 이 저장소에서
> 가장 무거운 작업이고, Vite dev 서버는 오래 띄워 둘수록 커진다.
>
> ★ `hs_err_pid*.log` · `replay_pid*.log` 는 크래시 잔재다 (한 쌍에 2MB 넘는다).
> `FE/android/.gitignore` 의 `*.log` 가 이미 막고 있으니 커밋되지는 않지만,
> 원인을 확인한 뒤에는 지운다.

#### ★ 광고 SDK 가 들어가면 빌드가 커진다 — 실측

| 언제 | 크기 | 비고 |
|---|---|---|
| 광고 SDK 이전 | 약 **33MB** | `55 §3` 이 "32MB"로 적은 그 구성 |
| **광고 SDK 이후 · 디버그 APK** | **약 38MB** [실측 2026-08-07 — `app-debug.apk` 38,362,049 바이트] | Google Mobile Ads + UMP |
| ★ **릴리스 AAB** | **32.1MB** [실측 2026-08-08 — `app-release.aab` 32,051,819 바이트] | 디버그 APK 보다 **6MB 작다** — 디버그 심볼·테스트 런타임이 빠진다 |

> ⚠ **위 세 줄은 서로 비교할 수 있는 숫자가 아니다.** 디버그 APK · 릴리스 AAB ·
> 사용자 다운로드 크기는 **셋 다 다르고**, 작은 순서는 언제나
> **다운로드 < AAB < 디버그 APK** 다. `55 §3` 의 "32MB" 와 여기 AAB 의 "32.1MB"
> 가 우연히 비슷한 것을 **같은 것을 잰 값으로 읽지 않는다.**

`56 §2.7` 은 증가분을 **+2~5MB** 로 추정했는데 실측은 **그 상단**에 붙었다.
이유는 이 저장소의 릴리스 빌드가 **`minifyEnabled false`** 이기 때문이다 —
R8 이 꺼져 있으면 광고 SDK 의 미사용 클래스가 그대로 남는다.

> ⚠ **위 숫자는 디버그 APK 다.** 스토어에서 사용자가 실제로 받는 크기는
> **AAB 분할 배포 뒤의 다운로드 크기**이고 더 작다 — Play Console 의 앱 번들
> 탐색기가 기기별 다운로드 크기를 보여 준다. **AAB 파일 크기와 다운로드 크기를
> 같은 것으로 보고하지 않는다.**
>
> ★ R8 을 켜는 것은 검토 대상이지만 **켠 빌드로 실기기에서 광고를 한 번 띄워 보기
> 전까지 켰다고 말하지 않는다** (`56 §2.7`). 광고 SDK 는 리플렉션을 쓴다.

## 2. Play Console 개인 계정 만들기

### 2.1 가입

1. https://play.google.com/console → **개발자 계정 만들기**
2. **계정 유형: 개인(Individual)** ← ★ 여기서 갈린다. §2.2 를 먼저 읽는다
3. 등록비 **US$25 (1회, 평생)** 카드 결제
4. **신원 확인** — 신분증(주민등록증/여권/운전면허) 사진 + 주소 확인
5. 승인까지 보통 **며칠**

### 2.2 ★ 개인 vs 사업자 — 시작 전에 결정한다

| | 개인 (Individual) | 사업자 (Organization) |
|---|---|---|
| 준비물 | 신분증 | 사업자등록증 + **D-U-N-S 번호** |
| 스토어에 표시되는 이름 | **본인 실명** | 상호 |
| **EU DSA 거래자 주소·전화** | **공개된다** (`53 §5.4`) | 사업장 주소 |
| 프로덕션 출시 전 조건 | **클로즈드 테스트 12명 × 14일** (§6) | 해당 없거나 완화 |
| 준비 시간 | 며칠 | 몇 주 (D-U-N-S 발급 포함) |

> ★★ **계정 유형은 나중에 바꾸기 매우 번거롭다.** 나중에 바꾸려면 계정을 새로
> 만들고 앱을 이전해야 할 수 있다.
>
> ⚠ **"무료 앱이니까 판매자 정보가 안 나온다"고 생각하지 않는다.** 유료 앱의
> 판매자 정보 노출은 사라지지만, **EU DSA 거래자 지위는 무료+광고에도 적용될
> 것으로 본다** — 광고 수익은 상업 활동이다 (`56 §4.1` [추정] · `53 §5.4`).
> 거래자로 등록하면 **주소와 전화번호가 스토어에 공개된다.** 실명·주소 공개가
> 곤란하면 **지금** 개인사업자 등록을 알아본다.
>
> 반대로 "일단 만들어 보고 판단하겠다"면 **개인으로 시작해도 된다.** 이 게임은
> 서버도 인앱 결제도 없어서 사업자여야만 할 이유가 기술적으로는 없다.

### 2.3 ★ 결제 프로필 — 어느 쪽이 필요한가

**여기가 유료 문서와 가장 크게 갈리는 자리다.** "결제 프로필"이라는 같은 이름의
것이 **두 개** 있고, 무료+광고에서는 **필요한 쪽이 반대**다.

| | Play 결제 프로필 (merchant) | **AdMob 지급 프로필** |
|---|---|---|
| 어디 | Play Console → 결제 및 구독 → 결제 프로필 | **AdMob → 지급** |
| 무엇을 위한 것 | **앱 판매 대금 · 인앱 결제 대금**을 받는다 | **광고 수익**을 받는다 |
| 이 게임에 필요한가 | ✗ **필요 없다.** 무료 앱이고 인앱 결제가 없다 | ○ **필수.** 없으면 수익이 쌓이기만 하고 나오지 않는다 |
| 세금 정보 | Play Console 쪽 | ★ **AdMob 쪽에서 따로 받는다** (§8.3) |
| 지급 경로 | Play → 은행 | **AdSense 계정을 경유해** 은행 (§8.2) |

> ★★★ **무료 앱을 내는 데 Play 결제 프로필은 만들 필요가 없다.** 그리고
> **결제 프로필은 계정에 한 번 연결되면 해제가 어렵다** — 필요 없는 것을
> "나중에 쓸지도 모르니" 만들지 않는다.
>
> ⚠ **그 대신 AdMob 쪽을 잊는다.** 무료 앱이라 "정산 설정할 게 없다"고 넘어가면,
> 광고는 정상적으로 나가고 수익도 집계되는데 **지급 기준액을 넘겨도 돈이 오지
> 않는다.** 지급 프로필과 세금 정보가 비어 있으면 AdMob 이 **지급 보류**로 잡고,
> 그 보류는 화면 안쪽에 있어서 보러 가기 전에는 보이지 않는다.

**AdMob 지급 프로필 준비물** (`56 §1.1` 2단계):
- 이름 · 주소 (Play 신원 확인과 **일치시키는 편이 낫다** — 다르면 확인 요구가 온다 [추정])
- **정산 받을 은행 계좌** (본인 명의 · 한국 계좌 가능)
- **미국 세금 정보 (W-8BEN)** — §8.3
- 주소 확인용 PIN 우편 (기준액에 처음 도달할 때 발송 [추정 — AdSense 관행])

노멀 · 하드 · 나이트메어. 나이트메어에는 월드마다 규칙이 하나씩 붙는다.

> ★ **"없는 것" 문단은 광고가 붙어도 여전히 이 게임의 판매 포인트다.**

> 확률형 없음은 `CLAUDE.md` 절대 규칙 6 이고, 인앱 결제 없음은 결제 SDK 자체가

> (`FE/src/native/ads.js`).

> ★★ **"광고에 대하여" 문단을 숨기지 않고 먼저 쓴다.** 광고형 게임에서
> 사용자가 가장 먼저 묻는 것은 "있느냐"가 아니라 **"강제냐"** 다. 세 줄이
> 답하는 것이 정확히 그것이고, **세 줄 전부 코드로 강제되어 있다** —

> `showRewarded` 넷뿐이라 전면·배너를 만들 방법이 없고 (`56 §5.4`),
> `npm run playthrough` 가 **광고 0회로 100 스테이지 완주**를 매번 검증한다
> (`56 §6.6`).
>
> ⚠ **여기에 "광고를 보면 골드 2배" 같은 수치를 쓰지 않는다.** 보상 수치는
> `ads.json` 한 줄이고 게이트 결과에 따라 바뀐다 (`56 §6.5` 는 아직 미결이다).
> **스토어 설명은 데이터보다 고치기 느리다.**

### 4.6 ★★★ "광고 포함" 선언 — 안 하면 릴리스가 막힌다

Play Console → **정책 → 앱 콘텐츠 → 광고**

| 문항 | 답 | 결과 |
|---|---|---|
| 앱에 광고가 포함되어 있습니까 | **예** | 스토어 리스팅에 **"광고 포함"** 배지가 붙는다 |

**"광고"의 범위는 우리가 파는 것이 아니라 앱 안에 표시되는 전부다.** 보상형만
있어도, 사용자가 눌러야만 나와도, 하루 1회여도 **예**다. 이 선언은 "광고로 돈을
버는가"가 아니라 **"사용자가 이 앱 안에서 광고를 보게 되는가"** 를 묻는다.

Play Console → **정책 → 앱 콘텐츠 → 광고 ID**

| 문항 | 답 |
|---|---|
| 앱이 광고 ID 를 사용합니까 | **예** |
| 용도 (복수 선택) | **앱 기능 · 광고 또는 마케팅 · 분석 · 사기 방지 및 보안·규정 준수** 중 해당하는 것 — `56 §4.1` 은 **광고/마케팅 · 분석 · 사기 방지** 셋으로 잡았다 |

> ★★ **광고 ID 선언은 "우리가 쓰겠다고 결정하는 것"이 아니라 이미 일어난 일을
> 신고하는 것이다.** `play-services-ads` 20.4.0 이상은 매니페스트 머지로
> **`com.google.android.gms.permission.AD_ID` 권한을 자동으로 넣는다**
> (`56 §2.4`). 즉 플러그인을 설치한 순간 APK 안에 그 권한이 이미 있다.
>
> **선언하지 않으면 릴리스가 차단되거나 경고 메일이 온다** —
> *"Your advertising ID declaration says your app does not use advertising ID,
> but…"* 이 경고는 **AAB 를 올린 뒤에** 오므로, 클로즈드 테스트 마지막 날에
> 만나면 그날 릴리스가 나가지 않는다.

> ⚠ **광고 포함 선언은 광고를 실제로 켜는 릴리스에 맞춰서 한다.**
> `ads.json:enabled = false` 인 1.0 을 올리면서 "예"로 선언하면, 심사자가
> 광고를 찾다가 못 찾는다 — 반대 방향의 불일치다. **선언은 SDK 설치 여부가
> 아니라 사용자에게 실제로 광고가 노출되는가를 따른다** (`58 §4.3` 이 스크린샷
> 재촬영 트리거를 같은 기준으로 잡았다).

### 4.7 ★ 타깃층 및 콘텐츠 설문 — 아동으로 분류되면 광고 수익이 사라진다

예전에는 등급 라벨의 문제였고 지금은 **수익 모델이 성립하는가**의 문제다.

## 6. 트랙 전략 — ★여기가 일정의 바닥이다

### 6.1 순서

| 트랙 | 무엇 | 기간 |
|---|---|---|
| **내부 테스트** | 최대 100명. 본인 계정만 넣어도 된다. **심사 거의 없이 즉시** | 즉시 |
| **클로즈드 테스트** | ★ 개인 계정 필수 관문 | **최소 14일** |
| 오픈 테스트 | 선택 | — |
| **프로덕션** | 실제 출시 | 심사 며칠 |

### 6.2 ★ 개인 계정의 클로즈드 테스트 요구

**2023년 11월 이후 만든 개인(Individual) 계정**은 프로덕션 출시 전에:

- **테스터 12명 이상**이
- **연속 14일 동안** 옵트인 상태를 유지해야 하고
- 그 뒤에 **프로덕션 액세스를 신청**해 승인받아야 한다

> ⚠ **정확한 인원·일수·조건은 Play Console 대시보드에 그대로 표시된다.**
> 진행률(예: "12명 중 8명 · 6일 남음")까지 보여주므로 **화면을 신뢰한다.**

**실무 요령:**

| | |
|---|---|
| **여유 있게 초대한다** | 12명이 요구면 **15~20명**을 초대한다. 중간에 나가는 사람이 반드시 있다 |
| **Google 계정(Gmail) 주소**가 필요하다 | 테스터가 옵트인 링크를 열어 "테스터 되기"를 눌러야 카운트된다 |
| 매일 플레이할 필요는 없다 | **옵트인 상태 유지**가 조건이다. 다만 실제로 플레이해 달라고 부탁한다 — 이게 첫 실사용 데이터다 |
| 오늘 시작한다 | 14일은 줄일 수 없다. **다른 모든 작업과 병렬로 굴린다** |
| ★ **이 14일이 광고 배선의 작업 시간이다** | AdMob 계정 · 광고 단위 · 동의 메시지 · 네이티브 설정을 이 기간에 만든다 (`56 §8` 2단계). 14일은 어차피 기다려야 하는 시간이다 |
| ★★ **테스터에게 광고를 눌러 달라고 하지 않는다** | §6.4 — 유도된 클릭은 무효 트래픽이고 **AdMob 계정 정지 사유**다 |

**Google 그룹으로 관리하는 것을 권장한다** — 개별 이메일 목록보다 추가/제거가 쉽다.

> ★★ **이 14일은 국가 확대에 다시 필요하지 않다** (2026-08-07 확인).
> 프로덕션 액세스는 **앱 단위 1회성 관문**이고 국가 설정과 무관하다 — 한국
> 테스터만으로 통과한 뒤 미국·EU 를 켜도 다시 돌지 않는다. **53번 §8.3.**
> 반대로 **새 앱(새 패키지명)을 만들면 처음부터 다시다** — 그래서 "영어권판"을
> 따로 만들지 않는다 (53 §8.1).
>
> ⚠ **2026-04 이후 Google 은 "테스터가 실제로 앱을 썼는가"를 본다.** 옵트인만 하고
> 아무도 안 켠 상태로 신청하면 참여도 부족으로 반려된다. 위의 "매일 플레이할 필요는
> 없다"는 **옵트인 유지 조건**에 대한 말이고, 신청서에는 **어떤 기능을 썼는지**를
> 적어야 한다 → 테스터에게 **이틀에 한 번은 열어 달라**고 부탁한다.

### 6.3 ★ 첫 AAB 는 손으로 올린다

**Google Play Publishing API 는 "아직 릴리스가 하나도 없는 앱"에 업로드할 수 없다.**
Codemagic 자동 업로드가 첫 시도에서 실패하는 가장 흔한 이유가 이것이다.

→ **§1.4 에서 만든 `app-release.aab` 를 내부 테스트 트랙에 손으로 한 번 업로드한다.**
그 다음부터 CI 가 동작한다.

### 6.4 ★★★ 클로즈드 테스트 14일 동안 광고를 어떻게 확인하는가

**가장 흔한 사고가 여기서 난다.** 릴리스 빌드에 실제 광고 단위 ID 가 들어가 있고,
테스터에게 "광고 잘 나오나 봐 줘"라고 부탁하고, 몇 명이 호의로 눌러 준다 —
그 순간 **무효 트래픽이고 AdMob 계정 정지 사유다.** 악의가 없어서 더 위험하다.

| 확인할 것 | 어떻게 | 어느 트랙 |
|---|---|---|
| 버튼이 뜨고 눌리는가 · 보상이 붙는가 | **테스트 광고 단위 ID** — 개발 빌드는 `import.meta.env.DEV` 로 **자동**이다 (`56 §1.3`) | 로컬 · 내부 테스트 |
| 릴리스 빌드에서 실제 광고의 로드 시간 · 크기 | ★ **테스트 기기 등록** — 실제 단위 ID + 등록된 기기 = **실제 광고가 뜨지만 노출·클릭이 집계되지 않는다** (`56 §7.2`) | 내부 테스트 |
| EU 동의 폼 | `debugGeography: EEA` 로 강제한다. 한국은 EEA 가 아니라서 **평소에는 폼이 뜨지 않는다** (`56 §7.4`) | 로컬 · 내부 테스트 |
| 몰입 모드 복귀 · BGM · 중도 이탈 | **실기기에서만 드러난다** (`56 §7.5`) | 내부 테스트 |
| 12명 테스터의 진행도 · 이탈 지점 | **광고와 무관하게 이것이 14일의 본래 목적이다** | 클로즈드 |

> ★★★ **테스터에게 나가는 빌드에는 광고를 넣지 않는 것이 가장 안전하다.**
> `56 §8` 이 1.0 을 광고 없이 내라고 권하는 이유가 여기에도 있다 —
> **12명에게 실제 광고를 띄우면 그 12명의 시청·클릭이 전부 내 계정의 첫
> 트래픽이 된다.** 지인 트래픽은 무효 트래픽으로 판정되기 쉽고,
> 판정은 **되돌리기 매우 어렵다.**
>
> 광고를 포함해 테스트해야 한다면 **내부 테스트 트랙 + 본인 기기 + 테스트 기기
> 등록**까지가 안전한 범위다. **클로즈드 트랙의 12명에게는 광고를 켜지 않는다.**

| ⛔ 절대 하지 않는 것 | 왜 |
|---|---|
| 실제 광고 단위 ID 로 뜬 광고를 **직접 클릭** | **계정 정지.** "잘 나오나 눌러 봤다"에서 나온다 |
| 테스터·지인에게 "광고 좀 봐 줘 / 눌러 줘" | 유도된 클릭도 무효 트래픽이다 |
| 심사 제출 빌드에 `ads.json:testMode = true` | 심사자가 테스트 광고를 본다. 정책 위반이고, 그대로 승인되면 **실제 광고가 영원히 안 뜬다** (`56 §7.3`) |
| `ads.json:enabled = true` 인데 `units.android` 가 빈 값 | 테스트 ID 로 조용히 떨어진다 → 수익 0. `check:prod` 에 이 규칙을 넣는다 (`56 §5.5`) |

**게임 자체는 여전히 아무것도 수집하지 않는다.** 서버 없음 · 분석 SDK 없음 ·

**바뀐 것은 광고 SDK 하나다.** 그리고 그 하나가 이 절의 답을 전부 뒤집는다.

| 광고 SDK | 없음 | Google Mobile Ads + UMP |
| 데이터 보안 양식 | 수집·공유 **아니오** | **예 · 4개 유형** (§7.1) |

> ★★ **두 종류의 데이터를 섞어 읽히지 않게 쓰는 것이 이 절의 요령이다.**
> 게임 데이터는 기기 밖으로 나가지 않고, 광고 데이터는 Google 이 가져간다.
> 방침이 그 구분을 명시하지 않으면 심사자가 하나로 읽는다 (`56 §4.2`).

### 7.1 데이터 보안 양식

Play Console → **정책 → 앱 콘텐츠 → 데이터 보안**

#### [1.0 광고 없음] — 예전 답 그대로

| 질문 | 답 |
|---|---|
| 데이터를 수집하거나 공유하는가 | **아니오** |
| 데이터가 전송 중 암호화되는가 | 해당 없음 (전송 없음) |
| 사용자가 데이터 삭제를 요청할 수 있는가 | **앱 삭제로 전부 삭제됨** |

> ★ **"수집(collect)"의 정의:** Google 기준으로 수집은 **데이터를 기기 밖으로
> 전송하는 것**이다. `@capacitor/preferences` 로 기기 내부에만 저장하는 것은
> 수집이 아니므로 **"아니오"가 정직한 답이다.** 여기서 겁을 먹고 "예"로 답하면
> 20여 문항이 열리고 App Store 라벨과 어긋나 불일치 반려가 난다 (53 §5.2).
> **이 문단은 광고가 붙어도 그대로 참이다** — 세이브는 여전히 수집이 아니다.

#### ★★ [광고 켬] — 화면에서 실제로 무엇을 누르는가

첫 문항 **"앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요?"** 에서
**예**를 누르는 순간 데이터 유형 트리가 열린다. 아래 **네 개만** 체크한다.

| 데이터 유형 (콘솔의 트리 경로) | 수집 | 공유 | 처리 | 목적 (복수 선택) |
|---|---|---|---|---|
| **위치 → 대략적인 위치** | ✅ | ✅ | 필수 | 광고 또는 마케팅 · 분석 · 사기 방지·보안 |
| **앱 활동 → 앱 상호작용** | ✅ | ✅ | 필수 | 광고 또는 마케팅 · 분석 |
| **앱 정보 및 성능 → 진단** | ✅ | ✅ | 필수 | 분석 |
| **기기 또는 기타 ID** | ✅ | ✅ | 필수 | 광고 또는 마케팅 · 사기 방지·보안 |

각 유형마다 따라 나오는 문항:

| 문항 | 답 | 왜 |
|---|---|---|
| 이 데이터가 **수집**되나요 / **공유**되나요 | **둘 다 예** | Google 로 나가고(수집), Google 이 광고 파트너에게 넘긴다(공유) |
| 수집이 **선택 사항**인가요 | **아니오 (필수)** | 광고를 켠 사용자가 끌 수 있는 항목이 아니다. 광고를 안 보는 것은 선택이지만 SDK 초기화 시점의 수집은 아니다 |
| 사용자가 데이터 **삭제를 요청**할 수 있나요 | **예** | 기기 설정에서 광고 ID 재설정·삭제. 방침 §5 에 방법을 적는다 |

마지막 공통 문항:

| 문항 | 답 |
|---|---|
| 데이터가 **전송 중 암호화**되나요 | **예** — Google 이 전부 TLS 라고 명시한다 [확인] |
| **독립적인 보안 표준 검증**을 받았나요 | 아니오 |

> ⚠ **위 매핑은 구글이 대신 해 주지 않는다.** 구글 문서는 *자신이 무엇을
> 수집하는지*만 말하고, **Play 데이터 보안 양식에 어떻게 답할지는 전적으로
> 개발자의 책임**이라고 명시한다 [확인 2026-08-07]. 근거와 원문 대조는
> **`56 §4.2`** 에 있다 — **콘솔 문항 문구를 읽고 다시 확인한다.**

> ⚠ **`AD_ID` 권한을 매니페스트에서 제거하면 "기기 또는 기타 ID" 행이 사라진다**
> (`56 §2.4`). 그러나 개인화 광고가 불가능해져 **eCPM 이 떨어진다** [추정].
> 이 게임은 광고 수익이 목적이므로 **켠 채로 두고 정직하게 선언한다.**

> **세 곳(개인정보처리방침 · 데이터 보안 양식 · App Store 개인정보 라벨)이 서로
> 달라선 안 된다.** 불일치는 심사 반려 사유다.
>
> ★ **iOS 로 나가면 넷이 된다** — `PrivacyInfo.xcprivacy`(Privacy Manifest)가 더
> 붙는다. **이 저장소에는 아직 그 파일이 없다** (2026-08-07 실측).
> 광고 버전의 전문은 **`56 §4.4`**, 광고 없는 버전은 53번 §5.3.
>
> ★★★ **광고를 켜면 셋이 아니라 여덟이 된다** — 개인정보처리방침 · Play 데이터
> 보안 · Play 광고 ID · Play 광고 포함 · Apple App Privacy ·
> `PrivacyInfo.xcprivacy` · Apple 연령 등급 설문 · 스토어 설명.
> **한 묶음으로 한 번에 고치는 체크리스트는 `56 §8` 4단계.**

### 7.3 ★★ 광고 포함 앱의 심사 마찰 — 자주 반려되는 사유

**광고가 없을 때 이 앱은 심사가 조용했다.** 서버도 결제도 권한도 없었기 때문이다.
광고 하나가 들어오면 **정책 표면이 통째로 열린다.** 아래는 이 게임의 구조에서
실제로 걸릴 수 있는 것만 추렸다.

| 반려 사유 | Play 가 무엇을 보는가 | 이 게임의 상태 |
|---|---|---|
| **광고가 게임 조작을 방해한다** (Better Ads Experiences) | 전면 광고가 **자연스러운 구분점이 아닌 곳**에서 뜨는가 — 게임 도중 · 콘텐츠 시작 시점 · 앱 실행 직후 | ✅ **해당 없음.** 보상형만이고 **결과 화면 한 곳**뿐이다. 그리고 **사용자가 명시적으로 옵트인한 보상형 광고는 이 정책의 적용 예외**다 [확인 2026-08-07] |
| **닫을 수 없는 광고** | 15초 뒤에도 닫히지 않는 전면 광고는 금지 | ✅ 보상형은 SDK 가 닫기 버튼을 제공한다 |
| **오도성 광고 배치** | 광고가 게임 UI(알림·경고·닫기 버튼)를 **흉내 내는가**, 실수 클릭을 유도하는 위치인가 | ✅ 광고 진입점은 결과 화면의 **명시된 버튼 하나**다. `56 §5.4` 가 배치 규칙을 고정한다 |
| ★ **아동 정책** | 타깃층에 13세 미만이 포함됐는데 5초 안에 닫을 수 없는 보상형·옵트인 광고를 띄우는가 | ⚠ **§4.7 에 걸린다.** 13세 미만을 하나라도 선택하면 **보상형 모델 자체가 금지된다** [확인 2026-08-07] |
| **광고 콘텐츠가 앱 등급을 넘는다** | 앱은 E10+ 인데 성인 광고가 나가는가 | ⚠ **AdMob 차단 설정에 달렸다** (§5) |
| **선언 불일치** | 광고 포함 · 광고 ID · 데이터 보안 · 개인정보처리방침이 서로 다른 말을 하는가 | ⚠ **여덟 곳을 한 묶음으로** (§4.5 · `56 §8` 4단계) |
| **동의 없이 광고 요청** (EEA) | UMP 폼을 거부한 사용자에게 광고가 나가는가 | ✅ 어댑터가 **`canRequestAds`** 로 판정한다 (`56 §3.1`). ⚠ 단 **AdMob 콘솔에서 GDPR 메시지를 게시하지 않으면 폼이 존재하지 않아** 조용히 위반이 된다 |
| **심사자가 광고를 못 찾는다** | 광고 포함으로 선언했는데 재현 경로가 없는가 | ⚠ 이 게임은 광고가 **스테이지 6 이상 · 하루 1회 · 결과 화면**이다. **심사 노트에 재현 경로를 적는다** |

> ★★★ **마지막 줄이 이 게임 고유의 위험이다.** `ads.json` 의 안전장치
> (`minStage: 6` · `dailyViews: 1` · `cooldownMs`)는 경제를 지키려고 넣은 것인데,
> **심사자 입장에서는 "광고 포함이라는데 광고가 안 나온다"** 로 읽힌다.
> 릴리스 노트가 아니라 **심사자용 노트 필드**에 이렇게 적는다:
>
> ```
> 보상형 광고는 스테이지 6 이상을 클리어한 뒤 결과 화면에서만 나타나며,
> 하루 1회로 제한됩니다. 재현: 새 슬롯 → 스테이지 1-6 클리어 → 결과 화면의
> "광고 보고 골드 N배" 버튼. 전면 광고와 배너 광고는 없습니다.
> ```
>
> **숫자와 버튼 문구는 실제 데이터에서 옮긴다** — 이 문서에 적힌 값이 아니라.
> 상한은 `ads.json`(`minStage` · `dailyViews`), 버튼 문구는
> `FE/src/i18n/messages/result.json:adWatch` 다. 보상 수치와 상한은
> `56 §6.5` 의 선택지 결정에 따라 **아직 바뀔 수 있다.**

## 8. 수익 · 세금 — 확인이 필요한 것들

> ★★★ **이 절은 2026-08-07 에 성격이 바뀌었다.** 예전에는 *"앱을 얼마에 팔
> 것인가"* 였고, 지금은 *"광고 수익이 어떻게 들어오는가"* 다. **돈이 지나오는
> 경로가 Play 가 아니라 AdMob → AdSense 로 완전히 다르다.**
>
> ⚠ **53번 §1 · §2 는 아직 유료 기준으로 쓰여 있다.** 가격 · 국가별 환산 ·
> Play 15% 프로그램 · Apple Small Business Program 절은 **무료 앱에 적용되지
> 않는다.** 다만 **W-8BEN · 외국 TIN · 한·미 조세조약** 설명은 광고 수익에도
> 그대로 유효하고, **제출하는 자리만 Play Console 에서 AdMob 으로 바뀐다** (§8.3).

### 8.1 가격 책정 — **해당 없음 (무료 앱)**

Play Console → 수익 창출 → 앱 가격 에서 할 일이 **없다.** 앱은 무료다.

> ★★★ **무료 → 유료 전환은 영원히 불가능하다.** §4.1 의 경고를 다시 읽는다.
> 이 문장은 이 문서에 두 번 나오는데, 그것이 의도다.

**대신 여기에 AdMob 수익 흐름을 적는다.**

#### 돈이 오는 경로

```
사용자가 보상형 광고를 끝까지 본다
        ↓  노출 1건
AdMob 이 집계 (eCPM × 노출 ÷ 1000 = 예상 수익)
        ↓  월말에 확정 (finalize)
AdMob 잔액에 반영
        ↓  잔액 ≥ 지급 기준액 이고 지급 보류가 없으면
지급 프로필(= 연결된 AdSense 계정)을 통해 은행 송금
```

| 항목 | 값 | 근거 |
|---|---|---|
| **지급 기준액** | **US$100** | [확인 2026-08-07 — AdMob 도움말 "Payment thresholds"] |
| **지급일** | 기준액을 넘긴 달의 **다음 달 21일경** | [확인] |
| **미달 시** | 다음 달로 **이월**되어 합산된다. 사라지지 않는다 | [확인] |
| **지급 정보 변경 마감** | 매월 **20일**. 21일 이후 변경은 **다음 달 주기**부터 적용 | [확인] |
| **eCPM (보상형 · 소규모 신규 앱)** | **$8 ~ $15** [추정] | `55 §1.2` |
| **광고 콘텐츠 등급 G 제한의 영향** | 위 값보다 **더 낮아질 수 있다** [추정] | `56 §9` 미결 항목 |

> ★★★ **이 게임에서 $100 은 먼 숫자다.** 현재 설정은 **배수 2.0 · 하루 1회**이고
> (`FE/src/game/data/ads.json` 이 권위다 — 이 문서도 56 도 아니다),
> 하루 1회로 묶이면 `55 §1.2` 가 가정한 **"설치당 17회 노출"이 성립하지 않는다.**
>
> ⚠ 그리고 그 설정은 **경제 게이트를 아직 통과하지 못한다** — `npm run economy`
> 가 "광고를 켜면 2개 구간(스테이지 80·90)에서 파워가 +20% 를 넘는다"고 경고한다.
> 사용자 결정은 **2배 유지 + 후반 재보정**(`56 §6.6`–`§6.7`)이고, 그 재보정 전에는
> `ads.json:enabled` 를 켜지 않는다. 실행 순서는 **`58 §2`** 다.
>
> eCPM $10 · 노출 1,000회 = **$10**. 기준액 $100 에 닿으려면 **누적 노출 약
> 1만 회**가 필요하다. **첫 지급까지 몇 달이 걸릴 수 있고, 그 사이 잔액은
> 이월된다.**
>
> **이것이 55 가 말한 "출구 없음"의 재무적 얼굴이다** — 경제를 지키면 광고가
> 안 벌고, 광고를 벌게 하면 경제가 깨진다. 벗어나는 길은 `56 §6.5` 의
> **선택지 C(골드가 아닌 보상)** 이고, **그 결정은 아직 미결이다.**

> ⚠ **출시 후 48시간 안에 AdMob 대시보드에서 노출이 잡히는지 확인한다.**
> 0 이면 수익 문제가 아니라 **배선 문제**다 — `56 §2.3`(매니페스트 앱 ID) ·
> `56 §1.2`(`~` 와 `/` 혼동)를 먼저 본다.

### 8.2 수수료 · 수익 배분

| | 유료 앱이었다면 | **무료 + 광고 (지금)** |
|---|---|---|
| Play 수수료 | 15% 또는 30% | ★ **없다.** Play 를 통해 오가는 돈이 없다 |
| 광고 수익 배분 | — | AdMob 이 자기 몫을 떼고 **나머지가 게시자 수익**이다 |
| 어디서 보나 | Play Console → 재무 | **AdMob → 홈 / 보고서** |

> ★ **AdMob 대시보드의 "예상 수익"과 eCPM 은 이미 배분이 반영된 값이다** [추정].
> 즉 표시된 수익에서 다시 몇 %를 빼는 계산을 하지 않는다. **정확한 요율은
> AdMob 화면에서 확인한다** — 이 문서보다 화면이 권위다.
>
> ⚠ **Play Console → 재무 화면은 무료 앱에서 거의 비어 있다.** 거기가 비었다고
> 수익이 없는 것이 아니다. **광고 수익은 Play Console 에 나타나지 않는다.**
> 두 화면을 헷갈리면 "광고가 안 나가는 줄" 알고 배선을 뜯게 된다.

### 8.3 세금 ★ 전문가 확인 필요 — **소득의 성격이 바뀌었다**

> **아래는 답이 아니라 "알아봐야 할 목록"이다. 세무사에게 확인한다.**

**가장 중요한 차이:** 이 수익은 **앱 판매 소득이 아니라 광고 수익**이다.
그래서 **세금 정보를 제출하는 자리부터 다르다.**

| | 유료 앱이었다면 | **무료 + 광고 (지금)** |
|---|---|---|
| 미국 세금 정보 제출처 | **Play Console → 결제 프로필** | ★ **AdMob → 지급 → 미국 세금 정보 관리** |
| 지급 주체 | Google (앱 판매 대금) | ★ **AdMob 에 연결된 AdSense 계정** |
| 양식 | W-8BEN 계열 | **W-8BEN 계열 (동일)** |
| 소득 구분 | 앱 판매 | **광고 게재 수익** |

> ★★ **AdMob 계정을 만들면 AdSense 계정이 함께 만들어진다** [확인 2026-08-07].
> AdMob 은 **지급을 AdSense 계정을 통해 처리하기 때문**이고, 이미 같은 Google
> 계정으로 AdSense 를 쓰고 있으면 그것에 **연결된다.** 그래서 지급·세금 화면이
> AdMob 안에 있으면서도 AdSense 의 규칙을 따른다.
>
> ⚠ **"Play Console 에서 세금 정보를 냈으니 됐다"가 되지 않는다.** 무료 앱에는
> Play 결제 프로필 자체가 없고(§2.3), 있다 해도 **AdMob 쪽 제출은 별개다.**
> 미제출 상태면 **미국 원천징수가 최고율로 잡힌다** — 유튜브·AdSense 에서
> 관측되는 미제출 기본 원천징수는 **24%** 다 [확인]. 한·미 조세조약을 적용하면
> **훨씬 낮아진다** (관측 사례에서 한국은 광고 유형에 따라 10% 대 [확인 —
> 2차 출처. 실제 적용 세율은 AdMob 화면의 계산 결과가 권위]).

**알아봐야 할 목록:**

| 무엇 | 확인할 것 |
|---|---|
| **미국 원천징수** | AdMob → 지급 → **미국 세금 정보**에서 W-8BEN 제출. **미제출로 두지 않는다.** 유효기간은 서명한 해 + 이후 3년 [확인] |
| **국내 소득 신고** | 앱 판매가 아니라 **광고 수익**이다. 사업소득인지 기타소득인지, 규모에 따라 사업자등록이 필요한지 |
| **부가가치세** | 국외 사업자(Google)로부터 외화로 받는 용역 대가의 취급. **앱 판매와 규정이 다르다** |
| **통신판매업 신고** | ⚠ **무료 앱이고 인앱 결제가 없으므로 판매 행위 자체가 없다.** 예전 문서는 "스토어를 통한 판매"를 전제했는데 **그 전제가 사라졌다.** 그래도 광고 수익 사업의 신고 의무를 별도로 확인한다 |
| **외화 수취** | 은행 계좌로 들어오는 외화 송금의 신고·증빙 |

### 9.4 `codemagic.yaml` ✅ **작성됨** (2026-08-08)

> ### ★★ 정본은 **저장소 루트의 `codemagic.yaml`** 이다
>
> §1.3 과 같은 이유로 여기에 전문을 복사해 두지 않는다. 예전에 이 자리에 있던
> 초안은 **클론 검증(§1.1) 전에 쓰인 것이라 지금 그대로 쓰면 조용히 실패한다.**
> 아래는 그 파일이 초안과 **무엇이 다른가**만 적는다.

#### 워크플로가 둘이다

| | 트리거 | 하는 일 | Play 업로드 |
|---|---|---|---|
| `android-verify` | `dev` · `main` push · PR | 게이트 + 웹빌드 + **키 없이** AAB 빌드 | ✗ |
| `android-release` | 태그 `v*` | 위 전부 + 서명 + 검증 | ○ 내부 테스트 |

`dev` 는 통합 브랜치라 자주 깨질 수 있으므로 Play 에 올리지 않는다 (§1.1).
`android-verify` 가 **키 없이** AAB 를 만드는 것은 §1.3 의 `canSignRelease`
가드가 살아 있는지를 매 push 마다 확인하기 위해서다 — 그 가드가 죽으면
**키 없는 환경의 빌드가 설정 단계에서 전부 죽는다.**

#### 초안과 달라진 것 넷

| 무엇 | 왜 |
|---|---|
| ① `npm run assets:all` 스텝 **삭제** | `prebuild` 가 이미 부른다. 그대로 두면 아틀라스·오디오 인코딩이 **두 번** 돈다 |
| ② `npm run check:prod` 대신 `node tools/check-production.mjs` | `check:prod` 는 `vite build` 를 한 번 더 돌린다. 방금 만든 `dist` 를 그대로 검사한다 |
| ③ **서명 환경변수 사전 검사 스텝 추가** | 아래 ★★★ |
| ④ **빌드 후 서명·`versionCode` 검증 스텝 추가** | 아래 ★★ |

> ### ★★★ ③ — `CM_*` 이름이 틀리면 조용히 서명 없는 AAB 가 나간다
>
> `build.gradle` 은 CI 자격증명을 `CM_KEYSTORE_PATH` · `CM_KEYSTORE_PASSWORD` ·
> `CM_KEY_ALIAS` · `CM_KEY_PASSWORD` 에서 읽는다 (§1.3). **이 이름들이 Codemagic 이
> 실제로 내보내는 이름과 다르면** `canSignRelease` 가 false 로 떨어지고 —
> **서명 없는 AAB 가 만들어지고 빌드는 `BUILD SUCCESSFUL` 로 끝난다.**
> 실패는 한참 뒤 Play 업로드에서 난다.
>
> ⚠ **이 이름들은 Codemagic 문서 기준이고 첫 실행 전까지 실측된 적이 없다.**
> 그래서 첫 스텝이 넷을 검사하고, 없으면 **이 빌드에 실제로 존재하는 `CM_*`
> 이름 목록을 출력하고 즉시 멈춘다** (값은 출력하지 않는다). 틀렸더라도
> **첫 실행 1분 안에, 정답과 함께** 알게 된다.

> ### ★★ ④ — `BUILD SUCCESSFUL` 은 "올바른 키로 서명됐다"가 아니다
>
> `:app:signReleaseBundle` 은 **키가 없어도 태스크 목록에 나타난다** (§1.4 실측).
> 그래서 빌드 뒤에 네 가지를 따로 검사한다:
>
> | 검사 | 실패 시 |
> |---|---|
> | AAB 파일이 존재하는가 | ★ "파일이 없다"와 "서명이 없다"를 **같은 메시지로 말하지 않는다** — 처음엔 그렇게 짰다가 깨뜨려 보고 고쳤다 |
> | `jar verified` 인가 | `canSignRelease` 가 false 로 떨어졌다 |
> | `CN=Unknown` 이 아닌가 | `-dname` 이 빠진 키다 (§1.2) |
> | `versionCode == VERSION_CODE_BASE + BUILD_NUMBER` 인가 · **1000 을 넘는가** | Play 는 이미 쓴 `versionCode` 를 거부한다. 오프셋이 조용히 0 이 되면 CI 가 손으로 태운 번호와 충돌하는데, 그 실패는 빌드가 아니라 **업로드에서** 나므로 한참 뒤다 |
>
> 추가로 `AD_ID` 권한 유무를 **보고**한다 (실패시키지는 않는다) — Play 광고 ID
> 선언(§4.6)과 어긋나면 여기서 먼저 보인다.
>
> ★ **다섯 분기를 전부 깨뜨려 확인했다** (2026-08-08): 변수 없음 · 변수 있음 ·
> 키 파일 없음 · AAB 없음 · 서명 없는 AAB · 정상 AAB.

> ### ⚠ 검증 게이트에 `balance:check` 를 넣지 않았다
>
> `npm run verify` 는 `economy` · `balance:check` · `playthrough` 까지 돈다.
> CI 게이트에는 `lint · test · data:validate · check · icons:check` 만 넣었다.
>
> **`balance:check` 는 지금 실패하는 것이 정상이기 때문이다** — 16/21 이고
> 하드 실패 2건(B3 · BN3)은 **사용자 결정 대기**이지 회귀가 아니다
> (`CLAUDE.md` · `docs/02-design/22-nightmare.md` §0-A.1). 넣으면 **모든 릴리스가
> 막힌다.** 결정이 나면 그때 넣는다.

> **`versionCode` 는 `$VERSION_CODE_BASE + $BUILD_NUMBER` 다** (§1.3).
> Codemagic 이 `BUILD_NUMBER` 를 자동 증가시키므로 손댈 것이 없다.
>
> **`triggering` 을 태그로 제한한 이유:** 커밋마다 Play 에 올리면 `versionCode` 를
> 낭비하고 트랙이 지저분해진다. 릴리스는 의도적인 행위여야 한다.
>
> ```bash
> git tag v1.0.0 && git push origin v1.0.0
> ```

> ★ **광고를 켜면 `check-production.mjs` 가 지켜야 할 것이 두 가지 늘어난다**
> (`56 §5.5`) — ① 배포 번들에 **테스트 광고 단위 ID 가 남아 있지 않은가**
> ② `ads.json:enabled === true` 인데 `units.android` / `units.ios` 가 **비어
> 있지 않은가**. 지금은 빈 값이면 안전한 방향(테스트 ID)으로 떨어지지만,
> 그 안전장치는 **"광고가 안 뜬다"로 조용히 나타난다.** **CI 가 빌드를 실패시키게 만든다.**
>
> ⚠ **CI 에는 실제 광고 단위 ID 가 필요 없다.** 그것은 `ads.json` 에 커밋되는
> 값이지 Codemagic 환경변수가 아니다. **AdMob 앱 ID 는 `strings.xml` 에 있고,
> 그 파일은 저장소에 있다** (`56 §2.3`) — 그래서 저장소를 private 로 둔다 (§1.1).


### 9.5 트랙을 올리는 법

`track:` 값을 바꾸고 태그를 다시 민다.

| 단계 | `track` |
|---|---|
| 내부 테스트 | `internal` |
| 클로즈드 테스트 (14일 관문) | `alpha` |
| 오픈 테스트 | `beta` |
| 프로덕션 | `production` |

> 또는 Play Console 에서 **"릴리스 승격"** 으로 이미 올라간 빌드를 다음 트랙으로
> 옮길 수 있다. 같은 AAB 를 다시 빌드할 필요가 없으므로 이쪽이 낫다.

### 9.6 밸런스 게이트는 CI 에 넣지 않는다

`npm run balance:check` 는 **300시드 · 약 2시간**이다. CI 빌드 시간을 통째로 먹는다.
→ **로컬에서 배경으로 돌리고, CI 에는 `lint · test · data:validate · check` 만 넣는다.**
(위 yaml 이 그렇게 되어 있다.)

## 11. 자주 막히는 곳

| 증상 | 원인 · 해결 |
|---|---|
| `invalid source release: 21` | CI 의 Java 가 21 미만. yaml 의 `java: 21` 확인. 로컬은 `JAVA_HOME` 을 명령마다 지정 |
| Codemagic 이 첫 업로드에서 실패 | **§6.3** — 첫 AAB 는 손으로 올려야 한다. 그리고 **1.0 은 CI 자체를 쓰지 않는다** (§9.0) |
| `Package not found: com.superdimension.app` | 서비스 계정이 아직 그 앱 권한을 못 받았거나, 앱이 생성만 되고 릴리스가 0개 |
| `versionCode` 중복 거부 ("이미 사용되었습니다") | 그 번호는 **영원히** 못 쓴다. 로컬은 `BUILD_NUMBER=<다음 숫자>` 로 다시 빌드, CI 는 `VERSION_CODE_BASE` 확인 (§1.3) |
| `gradlew: Permission denied` | yaml 에 `chmod +x gradlew` (§9.4 에 포함됨) |
| 서명 불일치 | 업로드 키가 바뀌었다. Play App Signing 의 업로드 키 재설정 요청 |
| `assets:pack` 이 CI 에서 실패 | `ffmpeg-static` 다운로드 실패 가능. 아틀라스를 커밋해 두고 `assets:audio` 만 건너뛰는 것도 방법 |
| 심사 반려: 개인정보처리방침 | URL 이 404 거나, 앱 이름이 문서에 없거나, 데이터 보안 양식과 불일치 |
| 프로덕션 신청 거부 | 클로즈드 테스트 조건 미달. 대시보드가 진행률을 보여준다. **2026-04 이후는 참여도(실제 사용)도 본다** (§6.2) |
| 스크린샷 거부 | 실제 게임 화면이 아니거나(과도한 편집), 규격 미달, 다른 기기 프레임 합성 |
| **EU 에서만 앱이 사라졌다** | ★ **DSA 거래자 지위 미설정.** 한국만 낼 때는 드러나지 않는다 → **53번 §5.4** |
| 영문 리스팅인데 개인정보 URL 이 한국어 문서 | 로케일별로 다른 URL 을 넣을 수 있다 → **53번 §5.1** |
| **앱을 유료로 만들고 싶어졌다** | ⛔ **불가능하다.** 무료→유료 전환은 없다 (§4.1). 새 패키지명으로 새 앱을 만드는 것뿐이고 그러면 클로즈드 테스트 14일을 다시 돈다 |

### 광고를 붙인 뒤에 새로 생기는 것

| 증상 | 원인 · 해결 |
|---|---|
| **설치는 됐는데 아이콘을 누르면 즉시 튕긴다** | ★★★ `AndroidManifest.xml` 의 `APPLICATION_ID` meta-data 누락. Mobile Ads SDK 는 앱 **부팅 시** 죽인다 → `56 §2.3`. logcat 을 `AdMob` 으로 필터 |
| 앱은 사는데 광고가 영원히 안 뜬다 | 앱 ID(`~`)와 광고 단위 ID(`/`)를 바꿔 넣었다 → `56 §1.2` |
| 릴리스 업로드가 차단 · **"advertising ID declaration"** 경고 메일 | Play 광고 ID 선언 누락 → **§4.6**. 플러그인이 `AD_ID` 권한을 자동으로 넣는다 |
| 심사 반려: **데이터 보안 불일치** | 방침 · Data safety · 광고 ID · 광고 포함이 서로 다른 말을 한다 → **§4.5 · §7.1** |
| 심사 반려: **광고를 찾을 수 없음** | `minStage` · `dailyViews` 때문에 재현이 어렵다 → **§7.3** 의 심사자 노트 |
| 심사 반려: **Better Ads Experiences** | 이 게임 구조에서는 걸리지 않아야 한다. 걸렸다면 배치가 결과 화면 밖으로 새어 나간 것 → **§7.3** · `56 §5.4` |
| **EEA 사용자에게 동의 폼이 안 뜬다** | AdMob 콘솔에서 GDPR 메시지를 **게시**하지 않았다. `isConsentFormAvailable` 이 false 로 오고 **아무 오류 없이 위반이 된다** → `56 §3.1` |
| 광고 버튼이 "로딩 중"으로 굳는다 | 중도 이탈 시 `showRewardVideoAd()` 가 **영원히 resolve 하지 않는다** → `56 §5.3` ① (어댑터가 이미 경주로 처리한다) |
| 광고를 닫고 오면 **시스템 바가 돌아와 있다** | `immersiveMode` 는 `prepare` 옵션이다 → `56 §5.3` ③ |
| **AdMob 대시보드 노출이 0** | 배선 문제다. `56 §2.3` · `§1.2` 를 먼저 본다 (§8.1) |
| 수익이 쌓이는데 **돈이 안 들어온다** | 지급 기준액 $100 미달로 이월 중이거나, 지급 프로필·세금 정보 미완으로 **지급 보류** → **§8.1 · §8.3** |
| Play Console 재무 화면이 **비어 있다** | 정상이다. **광고 수익은 Play 에 나타나지 않는다** → **§8.2** |
| CI 빌드가 어제는 됐는데 오늘 깨진다 | `play-services-ads` 가 **`24.7.+` 플로팅 버전**이다 → `56 §2.2` |
