# 29. 이중 언어 (한국어 · 영어)

> 2026-08-07 도입. 영어권 유료앱 출시가 목적이다 (`docs/06-release/53-english-market-paid-release.md`).
>
> **이 문서는 결정과 그 이유만 적는다.** 작업 절차와 함정 목록은
> `.claude/skills/i18n/SKILL.md` 가 갖고, 실행되는 규약은 `FE/tools/check-i18n.mjs` 다.
> 셋이 갈라지면 **코드가 맞고 문서가 버그다** (CLAUDE.md 절대규칙 10).

---

## 0. 왜 지금인가

한국어 기준으로 만든 것은 옳았다 (절대규칙 9 — 한글이 라틴의 약 2배 폭이라
한국어에 맞추면 영어는 들어가고 반대는 반드시 깨진다). 그런데 그 결정은
**문자열이 JSX 안에 그대로 박혀 있다**는 뜻이기도 했다. 조사 결과 사용자에게
보이는 문자열이 **약 1,260건** (코드 580 · 데이터 680), 한글 15,650자였다.

그리고 절대규칙 9 의 전제는 **이 폰트에서 거꾸로였다** — §4 참조.

## 1. 결정 다섯 가지

### ① 두 언어를 같은 자리에 나란히 적는다

```json
"title": { "ko": "방주", "en": "The Ark" }
```

`ko.json` / `en.json` 을 따로 두지 않는다. 이 저장소가 반복해서 당한 단일 실패
유형이 **"같은 사실을 두 곳에 적으면 갈라진다"**이고, 두 파일 구조는 그 사고를
**설계로 보장**한다 — 한쪽에 키를 더하고 다른 쪽을 잊으면 그 화면은 영어에서
`undefined` 를 그리고, 아무도 실패하지 않는다.

같은 원칙을 **게임 데이터에도** 적용했다. 동료 50 · 적 62 · 각인 18 의 이름을
카탈로그로 빼면 밸런스를 만지는 사람이 두 파일을 오가게 되고, 그 순간 둘이 갈라진다.
그래서 `game/data/*.json` 의 항목 **안**에 `{ko, en}` 을 둔다.

> 이 형태는 새로 만든 것이 아니다. `units.json` · `enemies.json` · `sigils.json` 의
> `name` 이 **처음부터 `{ko,en}`** 이었다(130건 · en 채워짐). 나머지 파일은
> `nameKo` 이거나 맨 한국어 문자열이었고 **세 가지 형태가 공존**하고 있었다.
> 가장 큰 세 집합이 쓰던 형태로 통일했다.

### ② 네임스페이스 하나 = 파일 하나

`FE/src/i18n/messages/<ns>.json` → 키는 `<ns>.<키>`.
카탈로그를 한 파일로 합치면 **병렬 작업에서 그 파일이 유일한 충돌 지점**이 된다
(이 저장소의 병렬 작업 규약: 파일 소유권). 실제로 이 작업은 에이전트 7개가
동시에 진행했고, 네임스페이스를 나눈 것이 그것을 가능하게 했다.

`import.meta.glob` 을 쓰지 않는다 — 편하지만 Vite 전용이라, 순수 Node 로 이 모듈
계통을 로드하는 하네스·검사기(`tools/*.mjs`)에서 그 자리가 터진다. 대신 `index.js` 에
명시적으로 import 하고, 빠뜨리는 실수는 `check:i18n` 의 I2 가 잡는다.

### ③ 언어는 모듈 스코프 값 하나다

`i18n/index.js` 의 `current`. React 밖(Phaser 씬 · `game/logic/` 의 라벨 함수)에서도
같은 답이 나와야 하기 때문이다. **시뮬레이션 수학은 이 값을 읽지 않으므로
결정론(절대규칙 1)은 영향을 받지 않는다** — 바뀌는 것은 표시되는 글자뿐이다.

React 는 그 값을 볼 수 없으므로 **`useT()` 훅이 스토어를 구독**한다. 컴포넌트에서
`t` 를 직접 import 하면 언어를 바꿔도 그 컴포넌트만 안 바뀐다.

### ④ 문장을 코드에서 결합하지 않는다

한국어와 영어는 어순이 다르다. `` `골드가 ${n} 부족합니다` `` 를 조각으로 옮기면
영어는 반드시 어색해진다. **문장 전체가 한 키**이고 자리표는 `{n}` 꼴이다.
ko/en 의 자리표 집합이 다르면 I3 가 잡는다.

### ⑤ 언어 전환 버튼은 **모든 화면 머리글**에 있다

사용자 요청("각 탭 혹은 메인 화면")이자 구조적 요구다 — **언어를 잘못 만난 사람은
설정을 찾아갈 수 없다.** 영어권 사용자가 한국어 화면에서 "설정"이라는 두 글자를
읽지 못하면 그 앱은 그 자리에서 끝나고, 유료앱에서는 곧 환불이다.

라벨은 언제나 **endonym** 이다 — 영어 화면에서도 `한국어`, 한국어 화면에서도
`English`. "Korean" 이라고 적으면 실수로 영어로 바꾼 사람이 되돌아올 단서를 잃는다.

## 2. 배선

| 무엇 | 어디 |
|---|---|
| 저장 | `settings.language` (`game/data/settings.json:defaults` · zustand persist) |
| 선택지 | `settings.json:options.language` — 이것이 없으면 `normalizeSettings` 의 검증 루프를 타지 않아 **어떤 값이 들어와도 그대로 저장된다** |
| 신규 계정 기본값 | `settingsSlice.defaultSettings()` → `detectLang()` (기기 로케일. `navigator` 가 없는 헤드리스에서는 `ko`) |
| 모듈 스코프 반영 | `App.jsx` → `setLang(v.language)` |
| `<html lang>` · `document.title` | 같은 자리 |
| 버튼 | `components/LangToggle.jsx` (전 화면 머리글) + 설정 화면의 정식 행 |
| 검사 | `npm run check:i18n` (`npm run check` 에 포함) |

> `language` 는 `settingsSlice.js` 의 **배선 표**에 등재돼 있다. `check:a11y` 의 A1 이
> 그 표와 `settings.json` 을 한 줄씩 대조하므로, **화면에 노출하는 것과 실제로
> 배선하는 것을 기계가 묶어 둔다** — 둘 중 하나만 하는 것은 애초에 불가능하다.

### 웹뷰 밖은 별도다

런처 아이콘 아래 글자는 **웹뷰의 i18n 이 절대 바꿀 수 없다.**
안드로이드는 `android/app/src/main/res/values-en/strings.xml`(추가함),
iOS 는 `InfoPlist.strings`(미작성). **OS 로케일이 정하며 앱 안의 설정과 동기화되지
않는다** — 그것이 정상이고, 그렇게 두는 것이 각 플랫폼의 규약이다.

## 3. 검사기 — 번역이 실패하는 다섯 가지 방식

`tools/check-i18n.mjs`. 다섯 가지 전부 **예외도 로그도 없이** 지나가고, lint 도
테스트도 잡지 못한다.

| 코드 | 무엇 | 증상 |
|---|---|---|
| I1 | 한 언어만 적음 · `en` 에 한글이 남음 | 그 자리가 비거나 영어 화면에 한글 |
| I2 | `messages/` 에 파일을 넣고 `index.js` import 를 잊음 | 그 네임스페이스 **전체**가 키 문자열 |
| I3 | 자리표가 한쪽에만 있음 | 영어 문장에서 숫자가 통째로 사라짐 |
| I4 | 카탈로그를 만들고 화면은 여전히 하드코딩 | 언어를 바꿔도 그 화면만 안 바뀜 |
| I5 | 데이터에 `en` 이 없거나 구형 형태 | 영어 화면에 한국어가 튀어나옴 |
| I6 | 없는 키 호출(오류) · 죽은 카탈로그 키(경고) | 화면에 키가 그대로 뜸 |

`PENDING` 집합은 **부채 목록**이다. 줄어들기만 해야 한다.

## 4. ★ 영어가 **더 넓다** — 절대규칙 9 의 전제 정정

`FE/src/assets/fonts/base_font.woff2` = 물마루 Mono. 실측:

| 항목 | 값 |
|---|---|
| ASCII 0x20–0x7E | **95/95 — 전부 있다** (폰트 교체 불필요) |
| Latin Extended-A (100–17F) | **0** — 체코·폴란드·터키어는 이 폰트로 불가능하다 |
| 한글 음절 | 11,172 / 11,172 |
| 라틴 advance | 96 (0.5 em) |
| 한글 advance | 192 (1.0 em) |

즉 **진짜 2:1 듀오스페이스**다. 그런데 낱말 단위로는 영어가 더 길다:

| | 비 |
|---|---|
| 동료 이름 50종 | 영어가 평균 **1.30배** 넓다 (40/50 종) |
| 적 이름 62종 | 평균 **1.19배** (44/62) |
| 최악 | `황금 갑충 여왕`(14) → `Royal Scarab Matriarch`(22) — **1.57배** |

**그러므로 "한국어에 맞추면 영어는 들어간다"는 참이 아니다.** 한국어에 맞춘 고정 폭
상자는 영어에서 말줄임된다. 위험 지점(말줄임·`nowrap` 이 걸린 CSS 16곳)은
`.enemyName{max-width:92px}` · `.roleTag{max-width:34px}` ·
`Meta.module.css .card{width:92px}` · `Settings.module.css .nav{width:128px}` · `.tab` 이다.

> 절대규칙 9 는 폐기하지 않는다 — **UI 를 한국어 기준으로 만든다**는 부분은 여전히
> 옳다(한글 조판이 더 까다롭고, 이 게임의 1차 시장이다). 정정되는 것은 그 뒤의
> "영어를 맞춘다"가 자동으로 성립한다는 **추론**이다. 두 언어를 다 봐야 한다.

## 5. 조용히 깨지는 두 곳

### ① 비트맵 폰트 글리프 화이트리스트
`game/pools/damageFont.js:DAMAGE_GLYPHS` 가 데미지 텍스트에 쓸 글자를 못박는다.
**Phaser BitmapText 는 폰트에 없는 문자를 경고 없이 건너뛴다.** 영어 문구를 쓰면서
A–Z 를 넣지 않으면 전투 중 숫자가 조용히 사라진다. `settings.json:damageTypeShort` 도
`{ko,en}`(`물/술/신` · `Ph/Ar/Ho`)이므로 **두 언어 값을 모두** 구워야 한다.

### ② `check-production.mjs` 의 마커
프로덕션 빌드의 디버그 잔재를 **"한글이 든 텍스트 덩어리"**(`HANGUL_RUN` 정규식)로
찾는다. UI 를 영어로 바꾸면 그 마커가 사라져 **거짓 통과**한다.
