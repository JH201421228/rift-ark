# 19. 아트 & 사운드 디렉션

> **핵심 제약: 유닛 스프라이트에 공격/이동/사망 애니메이션이 없다.**
> 몬스터 150종은 전부 **16×16 / 4프레임 아이들 루프**뿐이고, NPC 49종도 **32×32 / 4–6프레임 아이들**뿐이다.
> 이 문서의 절반은 그 제약을 **연출로 완전히 상쇄하는 방법**이다.

---

## 1. 아트 디렉션 — "HD 픽셀, 레트로 아님"

### 1.1 명제

**픽셀아트는 그 자체로 차별화가 아니다.** 2023–2025년 Steam에 픽셀아트 게임 6,422개가 나왔고 1만 장 이상 판매는 7–9.6%에 불과했다. 다만 **모바일**은 다르다 — 범용 애니 가챠 2.5D가 지배적인 피드에서 픽셀은 진짜로 튄다.

> **요구 조건: 픽셀아트가 레트로 향수가 아니라 의도적인 현대적 선택으로 읽혀야 한다.**
> 깔끔한 고프레임 연출, 채도 높은 팔레트, 현대적 파티클/라이팅, 다이내믹 카메라.

### 1.2 톤 — 어두운 세계 + 부조리한 병력

| 레이어 | 톤 |
|---|---|
| **배경 / 환경** | 어둡고 진지하다. 무너진 세계, 균열의 보랏빛, 다크 시네마틱 |
| **적 / 보스** | 위협적이다. 거대하고, 붉고, 화면을 흔든다 |
| **아군 병력** | **웃기다.** 성난 거위, 느림보 거북, 꼬꼬댁 닭이 진짜로 유용하다 |
| **UI / 이펙트** | **절대 개그치지 않는다.** 시각적 완성도가 높아야 대비가 산다 |

이 대비가 우리의 톤 훅이고, **에셋에 이미 들어 있어서 공짜다.**

### 1.3 픽셀 밀도 위계 (공식 규약)

| 계층 | 원본 | 배율 | 화면 | 소스px 크기 |
|---|---|---|---|---|
| 소형 동료/적 | 16×16 | ×4 | 64px | **4×4** |
| 대형 동료 | 32×32 | ×4 | 128px | **4×4** |
| 지휘관 | 96×80 | ×1 | 80px | 1×1 |
| 보스 | 80–250 | ×1~×4 | 280–400px | 1×1 ~ 4×4 |
| 이펙트 | 64×64 | ×2~×4 | 128–256px | 혼합 |

- **병력끼리는 픽셀 밀도가 완전히 동일하다** (소형·대형 모두 4×4) → 아트 일관성 완벽
- **지휘관과 최대형 보스만 밀도가 다르다** → **의도된 스케일 위계**로 규정한다: *굵은 픽셀 = 소모성 병력, 고운 픽셀 = 이름 있는 존재*
- **전 유닛에 동일한 1px 아웃라인** 을 적용해 의도적 스타일라이제이션으로 읽히게 만든다

### 1.4 팔레트

**월드별 색보정(ColorMatrix)으로 10개 월드를 시각적으로 분리한다.** 타일셋은 1개뿐이므로 색보정이 유일하게 저렴한 다양성 수단이다.

| 월드 | 색조 | 주 이펙트 색상행 |
|---|---|---|
| 1 하수도 | 탁한 녹갈 | 녹슨빛 `93,44,40` |
| 2 변경 | 회색+주황 | 회색 `47,47,47` |
| 3 늪 | 짙은 녹 | 초록 `17,83,57` |
| 4 성채 | 흙빛 | 녹슨빛 |
| 5 마법사탑 | 청보라 | 인디고 `31,0,144` |
| 6 지하묘지 | 청록+흑 | 흑청 `28,21,37` |
| 7 용의둥지 | 적황 | 진홍 `174,45,72` |
| 8 심연 | 자주+흑 | 보라 `58,41,76` |
| 9 천상 | 창백한 금 | 바이올렛 `36,15,62` |
| 10 균열핵 | 무채+보라 | 전 색상 순환 |

`effect/Free` 팩이 **9가지 색상 변형 행**을 제공하므로, 월드별로 다른 행을 쓰면 같은 이펙트가 완전히 다르게 보인다. **252 애니메이션 × 9색 = 2,268 조합**이 여기서 회수된다.

## 2. 애니메이션 없는 유닛을 살아 있게 만들기

**이 게임의 아트 성패가 여기에 달렸다.** 배틀캣츠·레전드오브슬라임 등이 검증한 접근이다.

### 2.1 상태별 연출 매핑

| 논리 상태 | 스프라이트 | 추가 연출 |
|---|---|---|
| **대기 (Idle)** | 4프레임 루프, 8fps | 미세 상하 바운스 (±1px, 사인파) |
| **이동 (Move)** | **동일 아이들 루프** (12fps로 가속) | 상하 바운스 ±2px + 이동 방향 기울기 3° + 발밑 먼지 파티클 |
| **공격 (Attack)** | **동일 아이들** | **① 전방 8px 돌진 (80ms, ease-out)**<br>**② 리코일 −4px (120ms, ease-in)**<br>**③ 스쿼시 1.15×0.85 → 1.0**<br>**④ 이펙트 스프라이트 재생 (타겟 위치)**<br>**⑤ 히트스톱 40ms** |
| **피격 (Hurt)** | 동일 아이들 | **① 흰색 틴트 플래시 60ms**<br>**② 넉백 −3px**<br>**③ 스쿼시 0.85×1.15**<br>**④ 히트 파티클 4개** |
| **사망 (Death)** | 동일 아이들 | **① 붉은 틴트 → 흰색**<br>**② 300ms 동안 회전 720° + 스케일 →0 + 알파 →0**<br>**③ 소멸 지점에 이펙트 재생 (`effect/` 폭발/연기 계열)**<br>**④ 파티클 8개 방사** |
| **소환 (Spawn)** | 동일 아이들 | **① 알파 0→1 (150ms)**<br>**② 스케일 0.6→1.15→1.0 (탄성)**<br>**③ 바닥에 소환 링 이펙트**<br>**④ 짧은 화면 밝기 펄스** |
| **스턴/빙결** | 프레임 정지 | 청색 틴트 + 위에 상태 아이콘 |
| **버프** | 동일 아이들 | 발광 아웃라인 + 상승 파티클 |

> **모든 값은 데이터.** `UnitPresenter` 컴포넌트가 유닛 타입별 연출 프로파일을 JSON에서 읽는다 (`03-tech/24-data-schema.md`). 근접 유닛은 돌진 거리가 크고, 원거리는 리코일만 있고, 공성은 반동이 크다.

### 2.2 공격 연출 = 3요소 조합

```
공격 = [유닛 트윈] + [발사체 또는 임팩트 이펙트] + [히트 반응]
```

| 역할 | 유닛 트윈 | 이펙트 | 히트스톱 |
|---|---|---|---|
| 방벽 | 돌진 4px | 소형 임팩트 | 20ms |
| 근접 | **돌진 10px** | 베기 이펙트 (Part 16–20) | 40ms |
| 원거리 | 리코일 −5px | **발사체** (`projectile/`) → 명중 시 소형 임팩트 | 25ms |
| 술사 | 상승 3px + 발광 | **대형 광역 이펙트** (Part 28–36) | 60ms |
| 공성 | 반동 −8px + 화면 흔들림 | 포물선 발사체 → 대형 폭발 | 80ms |
| 지원 | 펄스 | 상승 힐 이펙트 | 0 |

**★ 위 '이펙트' 열은 물리 타격의 모양이다. 술식·신성은 그림 자체가 다르다** (2026-08-05).

| 데미지 타입 | 일반 | 거대화·보스 |
|---|---|---|
| 물리 | 역할이 정한 모양 (베기 · 둔격 · 관통 · 타격) | 같은 그림 ×1.6 |
| 술식 | `arcane_hit` | `arcane_burst` |
| 신성 | `holy_hit` | `holy_burst` |

표는 `presenters.json:hitEffect` 에 있고 코드에는 없다. 색(`fx.json:damageTypeTint`)만
바꾸면 **파란 칼자국**이 될 뿐이고, 색각 이상 사용자에게는 차이가 0 이다 —
상성이 이 게임의 심장이라면 화면에서 **모양으로** 읽혀야 한다.
거대화가 배율이 아니라 다른 그림인 이유도 같다: 12프레임을 1.6배 늘리면
보스의 한 방이 잡몹 타격의 확대판으로 보인다.

지휘관 평타는 `presenters.json:commander.attack` 이 정한다 (병사와 다른 검격 `slash_b`).

> **발사체를 쓰는 역할(원거리 · 술사 · 공성)에는 타격 이펙트를 붙이지 않는다.**
> 발사체가 날아가는 중에 표적에서 타격이 먼저 터지면 인과가 뒤집힌다.

### 2.3 히트스톱과 카메라

**히트스톱(hit stop)이 픽셀 게임의 타격감을 만드는 가장 저렴한 도구다.**

| 이벤트 | 정지 | 카메라 |
|---|---|---|
| 일반 타격 | 20–40ms | — |
| 크리티컬 | 70ms | 셰이크 2px, 100ms |
| 광역 폭발 | 60ms | 셰이크 3px, 150ms |
| 엘리트 처치 | 100ms | 셰이크 4px + 줌 1.05× 200ms |
| 보스 페이즈 전환 | **400ms** | 줌 1.2× + 비네트 + 슬로우모션 |
| 방주 피격 | 50ms | 셰이크 5px + 붉은 비네트 펄스 |
| 템포 시프트 | 200ms | 셰이크 4px + 색보정 전환 |

**설정에서 화면 흔들림 강도 조절 가능** (100% / 50% / 끄기). 접근성 및 저사양 대응.

### 2.4 엘리트·보스 외곽선

**잡몹 무리 속에서 "저 놈이 다르다"를 한눈에 가려내는 장치.**
`enemies.json` 의 `art.outline` 이 있는 적(엘리트·보스 10종)에게만 붙는다.

- **색은 데이터**(`enemies.json:art.outline`), **두께·투명도·맥동은 프로파일**
  (`presenters.json:outline`). 적 10종에 같은 두께를 열 번 적지 않는다.
- 구현은 본체 뒤에 깐 **색 실루엣 스프라이트**다 — 1px 확대 후 `setTintFill`.
  반복 생성되므로 풀링한다 (절대규칙 8).
- 두께는 화면 두께(px)에서 **역산한다.** 고정 배율로 두면 ×2 인 대형 보스는
  외곽선이 두 배로 두꺼워지고 ×4 인 잡몹은 얇아져, 같은 표시가 적마다 다르게 보인다.

> **`postFX.addGlow` 를 쓰지 않았다.** postFX 는 WebGL 전용인데 이 저장소는 저사양
> 기기에서 일부러 CANVAS 로 부팅한다 — glow 로 만들면 **하필 그 기기에서만**
> 엘리트 표시가 사라진다. 그리고 glow 는 블러라 픽셀 위계를 흐린다.
> 상세: `03-tech/24-data-schema.md` §2.1.

### 2.4-A 발밑 피아 표식 (2026-08-05)

**"어느 쪽이 내 편인가"를 스프라이트에게 묻지 않는다.**

사용자 제보: *"적군과 아군의 피아를 확실하게 식별할 수 있었으면 좋겠어.
그래픽 상으로는 구분이 잘 안돼."* 실제로 단서가 없었다 —

| 기대했던 단서 | 왜 안 되는가 |
|---|---|
| 스프라이트 그림 | **양 진영이 같은 시트**에서 온다 (몬스터 150종·NPC 49종을 나눠 쓴다) |
| 바라보는 방향(`flipX`) | 16×16 4프레임 그림은 **대칭인 것이 많다** (발사체가 같은 이유로 방향을 못 냈다 — §2.2) |
| 체력바 색 | 아군 바는 **피해를 입은 뒤에만** 뜬다 (막대밭 방지). 만피 아군에게는 아무것도 없다 |

**해법 — 발밑에 상시 표식.**

- **아군 = 채운 하늘색 타원 · 적 = 빈 붉은 링.** 색이 아니라 **모양**이 1차 단서다.
  색약 모드에서도, 방주가 맞아 화면 전체가 붉게 물드는 순간에도 갈린다.
- 수치는 전부 `presenters.json:sideMark` — 색·비율·선 두께 어느 것도 코드에 없다.
- 크기는 **스프라이트 폭에서 파생**한다 (§2.4 외곽선과 같은 이유).
- **유닛 뒤**에 그린다 (depth 60 < 유닛 100). 발밑을 덮으면 픽셀아트가 상한다.
- `Graphics` 는 화면당 **둘**이다 — 체력바(유닛 위)와 표식(유닛 아래)은 depth 가
  달라야 하고 Graphics 는 depth 를 하나만 갖는다. 지켜야 할 명제는 "하나"가 아니라
  **"개체 수에 비례해 늘지 않는다"** 이다 (§2.5).

> ★ **표식은 만피 아군 `continue` 위에 있어야 한다.** 아래로 내리면 정확히
> 고치려던 그 경우(만피 아군)에만 안 그려진다. `EnemyBadges.test.js` 가
> 그 배치를 검사하고, 일부러 옮겨 실패를 확인했다.

## 3. 전장 배경

### 3.1 문제

`tilemap/` 은 **플랫포머용 던전/성채 타일셋**이고, 시차 스크롤용 원경 레이어가 **없다.**

### 3.2 해법 — 3레이어 `TileSprite` 시차

타일셋 조각을 조합해 **월드당 3장의 가로 타일링 배경 텍스처**를 제작한다.

| 레이어 | 스크롤 계수 | 내용 | 제작 |
|---|---|---|---|
| **원경 (Sky)** | 0.00 | 하늘/균열 그라디언트 + 실루엣 | 자체 제작 (단순 그라디언트 + 실루엣) |
| **중경 (Far)** | 0.15 | 무너진 구조물 실루엣 | `mainlevbuild.png` 조각 조합 후 어둡게 |
| **근경 (Mid)** | 0.45 | 벽·기둥·장식 | `mainlevbuild` + `decorative.png` |
| **지면 (Ground)** | 1.00 | 레인 3개의 바닥 타일 | `mainlevbuild` 바닥 타일 |
| **전경 (Fore)** | 1.30 | 흐릿한 기둥, 파티클 | 선택적, 월드 5+ |

```js
// 시차 갱신 (Phaser)
update(_, delta) {
  const s = this.scrollSpeed * delta / 1000;
  this.far.tilePositionX  += s * 0.15;
  this.mid.tilePositionX  += s * 0.45;
  this.ground.tilePositionX += s * 1.00;
}
```

**월드당 배경 제작 비용:** 원경 1장 + 중경 1장 + 근경 1장 = **3장 × 10월드 = 30장.** 타일셋 조합이므로 아티스트 1명 기준 월드당 반나절.

### 3.3 환경 애니메이션

`tilemap/` 의 `torch_1..4`(16×16), `spike_0..4`, `candleA/B` 를 **Tiled 오브젝트 레이어로 배치**하고 루프 재생. 살아 있는 배경 연출을 거의 공짜로 얻는다.

### 3.4 균열 (우측 스폰 지점)

게임의 시그니처 비주얼. 자체 제작 필요.
- 세로로 찢어진 보랏빛 균열, 상시 애니메이션

### 5.2 아이콘 정책 (2026-08-02 확정)

**아이콘 출처는 둘 뿐이다. 이모지·유니코드 글리프(★ ⚠ ✦ ❚❚ ▲)를 UI에 쓰지 않는다.**

| 구분 | 출처 | 예 |
|---|---|---|
| **게임 세계관 아이콘** — 재화·등급·전투 개념 | **에셋 아이콘** (Raven Fantasy, `sheets/icons-32.png`) | 골드 · 젬 · 강화석 · 파편 · 별 · 랭크 |
| **시스템 UI 아이콘** — 기계 장치 | **lucide-react** | 일시정지 · 리롤 · 경고 · 힌트 · 닫기 · 광고 |

**왜 나누는가.** 픽셀 유닛 옆에 벡터 라인 아이콘으로 '골드'를 그리면 두 세계가 섞여
어느 쪽도 진짜로 보이지 않는다. 반대로 일시정지 버튼을 픽셀로 그리면 기계 장치가
게임 오브젝트처럼 보여 오조작을 부른다. **경계는 "이것이 게임 세계 안에 존재하는가"** 다.

**왜 이모지를 금지하는가.** 이모지는 기기·OS마다 글리프가 다르다. 안드로이드에서
`⚠` 는 노란 삼각형이고 iOS에서는 흰 삼각형이며, 일부 기기에서는 두부(□)가 된다.
게임 톤과도 무관하게 렌더되고, 크기·정렬을 제어할 수단이 없다.

**구현**
- 에셋 아이콘: `<GameIcon name="currency.gold" />` — 좌표는 `src/game/data/icons.json`
  에만 있다 (절대규칙 5: 에셋 경로 하드코딩 금지). 리스킨은 이 JSON 만 바꾼다.
- lucide: 각 파일에서 직접 import. 기본값(크기·선 굵기)은 `App.jsx` 의 `LucideProvider`.
  `absoluteStrokeWidth` 를 켠다 — 끄면 12px 로 줄일 때 선까지 굵어져 픽셀 폰트 옆에서 뭉친다.
- 정렬 보정은 `index.css` 의 `#ui-overlay svg.lucide` 한 곳에만 있다.

**아이콘만 두지 않는다.** 재화 표기는 항상 `아이콘 + 한글 라벨 + 수치` 다.
아이콘만 두면 FTUE에서 "이 그림이 무슨 재화인지"를 배우는 비용이 생긴다.

> 5.1 표의 "별 2상태 / 데미지 타입 / 적 태그" 자체 제작 항목은 여전히 유효하다.
> Raven 선별본은 **임시 채움**이며, 자체 픽셀 UI 키트가 나오면 `icons.json` 의
> 좌표만 교체한다.

### 6.2 레이어드 BGM — 템포 시프트의 청각 표현

퍼커션 루프가 **BPM별로 3곡** 있다는 것이 큰 자산이다.

```
1막: [베이스 퍼커션 루프]                        volume 1.0
2막: [베이스 퍼커션 루프] + [시네마틱 드럼]      크로스페이드 800ms
3막: [베이스] + [시네마틱 드럼] + [드럼 전용]    강도 최대
```

**끊김 없이 강도가 오르는 체감**을 만든다. 곡을 바꾸는 게 아니라 레이어를 더한다.

### 6.4 오디오 기술 규격

| 항목 | 값 |
|---|---|
| BGM 포맷 | **OGG Vorbis ~96kbps 모노** + M4A 폴백 (iOS) |
| SFX 포맷 | OGG ~64kbps 모노 |
| **동시 재생 채널 상한** | **모바일 4** (데스크톱 16) — 모바일은 다중 오디오에 취약 |
| BGM 로딩 | 지연 로딩, 씬 진입 시 |
| 볼륨 | BGM / SFX 개별 슬라이더, 기본 BGM 60% SFX 80% |
| 백그라운드 | `App.pause` 에서 전체 뮤트, `resume` 에서 **AudioContext 재개 필수** |

**동일 SFX 중복 재생 제한:** 같은 SFX가 60ms 이내에 다시 요청되면 무시한다. 스웜 유닛 20마리가 동시에 공격할 때 오디오가 뭉개지는 것을 방지.

### 6.5 햅틱

`@capacitor/haptics` 사용. **기본 ON, 설정에서 끄기 가능.**

| 이벤트 | 강도 | 배선 |
|---|---|---|
| UI 탭 | Light | `hapticTap` — HUD · 설정 · 모달 · 각인 드래프트 |
| 유닛 소환 | Light | `hapticTap` — HUD 슬롯 탭 |
| 크리티컬 | Medium | `hapticHit` — `BattleScene.onDamage` (kind 4) |
| 방주 피격 | Medium | `hapticHit` — `BattleScene.onBreach` (`EV.BREACH`) |
| 패배 | Heavy | `hapticHeavy` — `BattleScreen` |
| ~~엘리트 처치~~ | — | **없다** (아래) |
| ~~보스 페이즈 전환~~ | — | **없다** (아래) |

> **`hapticHit` 은 2026-08-05 까지 정의만 있고 호출이 0건이었다.** 크리티컬도
> 방주 피격도 진동하지 않았고, 설정의 "진동" 스위치는 사실상 UI 탭에만 걸려 있었다.
> `src/game/wiring.test.js` 의 **W3** 이 이제 `haptics.js` 가 내보내는 `haptic*`
> 함수가 **전부** 어딘가에서 불리는지 검사한다.

> **엘리트 처치·보스 페이즈 전환은 일부러 넣지 않았다.** `EV.DEATH` 는 적의
> 정의 id 만 싣고 "엘리트인가"는 싣지 않으며, 씬이 그것을 판정하려면 규칙이
> 씬으로 새어 들어온다. 보스 페이즈는 이미 줌 · 셰이크 · 배너 · 태그 칩 넷이
> 동시에 말한다 — 채널을 다섯째로 늘릴 근거가 실기기 체감 전에는 없다.
> 넣기로 한다면 **시뮬 이벤트에 플래그를 싣는 쪽**이 먼저다.

**전투 중 햅틱 빈도 상한: 초당 3회.** 초과 시 무시 (배터리 및 불쾌감 방지).
상한은 `native/haptics.js` 한 곳에 있다 — 호출부에서 또 세지 않는다.

**끄는 스위치:** 설정 > 접근성 > **진동** → `App` 이 `setHapticsEnabled` 로 전달한다.
이 스위치가 위의 모든 경로를 끈다 (모듈 안에서 걸러지므로 호출부가 늘어도 새지 않는다).
