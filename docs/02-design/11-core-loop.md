## 1. 전장 구조

### 1.1 좌표계 (디자인 해상도 1280 × 720)

```
 y=0   ┌──────────────────────────────────────────────┐
       │  HUD 상단: 방주 HP · 웨이브 · 일시정지        │  0–80
 y=80  ├──────────────────────────────────────────────┤
       │  하늘 / 원경 시차 레이어                      │
 y=192 │═══ 공중 레인 (AIR) ═══════════════ y=224 ════│  ← FLYING 전용
 y=272 │─── 레인 0 (전방) ─────────────── y=320 ──────│
 y=368 │─── 레인 1 (중앙) ─────────────── y=416 ──────│
 y=464 │─── 레인 2 (후방) ─────────────── y=512 ──────│
 y=560 ├──────────────────────────────────────────────┤
       │  HUD 하단: 동료 6슬롯 · 주문 4슬롯(12종 중)   │  560–720
 y=720 └──────────────────────────────────────────────┘
        x=96                                     x=1184
       방주 벽                                    균열
```

- **레인 3개 + 공중 레이어 1개.** 지상 레인 baseline y = **320 / 416 / 512** (간격 96px)
- 유닛은 16×16을 **×4 스케일 = 64×64** 로 렌더, 발밑이 baseline에 정렬
- **깊이 정렬:** 레인 인덱스가 큰(후방) 쪽이 먼저 그려진다. 같은 레인 내에서는 x가 큰 쪽이 위에
- **방주 벽 x=96, 균열 x=1184.** 유효 전장 폭 **1088px**

> 좌표 상수의 단일 진실 원천은 `src/game/config.js` 의 `LANES` 와 `SPRITE_SCALE` 이다. 이 다이어그램은 그 의도를 설명한다.
- **성 HP는 3레인 공유** — 한 레인이 뚫려도 즉사가 아니라 관통 유닛이 방주를 때린다. 2레인을 내주고 1레인에 올인하는 플레이가 성립

### 1.2 레인 선택

- 동료 소환 시 **레인을 지정**한다. 기본은 마지막 선택 레인, 슬롯을 위/아래로 드래그하면 레인 변경
- **원터치 소환 모드**(설정, 기본 ON): 탭하면 "가장 비어 있는 레인"에 자동 배치. 캐주얼 접근성 보장
- 공중 적은 레인 개념 없이 y=112 라인을 직진한다. 지상 유닛 중 `ANTI_AIR` 태그가 있는 유닛만 요격 가능

## 2. 자원

### 2.1 마나 (동료 소환)

| 항목 | 값 |
|---|---|
| 시작 마나 | 60 |
| 기본 재생 | **6.0 / 초** |
| 최대치 | 200 (기록보관소 업그레이드로 300까지) |
| 템포 시프트 후 재생 | **12.0 / 초** |

**소환 코스트 상승 (안티스팸)**
```
cost(type) = base_cost × 1.18^n(type)
n(type) : 이번 전투에서 해당 타입을 소환한 횟수
감쇠   : 12초마다 n -= 1 (하한 0)
표시   : 슬롯에 현재 실 코스트를 항상 표시하고, 상승 중이면 ▲ 아이콘
```
- **전역이 아니라 타입별**이므로 "다양화"가 자연스러운 반격이 된다
- 12초 감쇠가 있어 완전 봉쇄가 아니라 리듬 강제. 후반 올인 스팸은 여전히 가능하되 비싸다
- 4연속 같은 유닛 소환 시 코스트는 1.0 → 1.18 → 1.39 → 1.64 → 1.94배

**처치 환급:** 적 처치 시 마나 `+floor(적_코스트 × 0.15)`. 공격적 플레이가 스스로를 먹여 살린다.

### 2.2 균열력 (지휘관 주문)

| 항목 | 값 |
|---|---|
| 시작 | 0 |
| 기본 재생 | **2.0 / 초** |
| 최대치 | 100 |
| 처치 보너스 | 적 1체당 +0.5 |

주문 코스트 예시: 파쇄 일제사격 22 / 균열 낙뢰 25 / 방주 수리 50 (§4.4).
주문은 **개별 쿨다운도 함께** 갖는다(연속 사용 방지).
가장 싼 4종을 들고 나가도 가득 찬 균열력 하나로는 전부 쏠 수 없다 — 그 부등식이 장착 4칸을 선택으로 만든다.

### 2.3 골드 (메타)

전투 중에는 사용처가 없고 결과 화면에서 정산된다.
```
gold = (처치수 × 스테이지_계수) + 클리어_보너스 + 별_보너스
```
> **팔라독/카툰워즈의 "일부러 천천히 죽여 파밍" 최적해를 원천 차단한다.** 골드는 **웨이브 격퇴 수**와 **클리어 여부**에만 연동하고, 전투 시간에 반비례하는 **속도 보너스**를 둔다. 느리게 하면 손해다.

## 3. 전투 수학

### 3.1 데미지 공식

```
물리:  dmg = max(ATK × 0.1,  ATK - DEF)
술식:  dmg = max(ATK × 0.1,  ATK × (1 - RES/100))          # DEF 완전 무시
신성:  dmg = max(ATK × 0.1,  ATK × (1 - RES/100)) × holyMul
       holyMul = 1.6 (CORRUPT) / 0.7 (LIVING) / 1.0 (그 외)
```

- **최소 피해 10% 보장** — "내 유닛이 아무것도 안 한다" 좌절 방지. 단, 10%는 사실상 무력하므로 상성은 여전히 결정적
- `DEF` 는 절대값 감산, `RES` 는 비율 감산. 두 방어 스탯이 **성격이 다르므로** 적 설계 폭이 넓어진다
  - 고DEF 저HP = 다단히트에 강하고 큰 한 방에 약함
  - 고RES 고HP = 술식에 강하고 물리 누적에 약함

### 3.2 공격 처리

```
attackInterval = base_interval / (1 + hasteBonus)
공격 시:  타겟 선정 → 데미지 계산 → 이펙트 재생 → 트윈(돌진/리코일)
```
- 타겟 선정: **같은 레인, 사거리 내, x가 가장 가까운 적**. 공중 적은 `ANTI_AIR` 만 대상 지정
- 레인이 1차원이므로 타겟 탐색은 정렬 배열의 이웃 조회로 **O(1)** (`03-tech/22`)
- 타겟 선정은 **앞뒤 양방향**이다 (자기보다 방주 쪽에 있는 적도 사거리 안이면 때린다)

> ★★ **아군 이동도 양방향이다** (2026-08-05, 사용자 제보 "균열까지 간 아군이 뒤의 적을
> 공격하지 않는다"). 예전에는 타겟 선정만 양방향이고 **이동은 +x 단방향**이라,
> 균열 끝까지 걸어간 아군은 자기를 지나쳐 간 적이 사거리를 벗어나는 순간
> **영원히 아무것도 하지 않았고** 그 적은 저항 없이 방주까지 갔다.
>
> 규칙: **앞(균열 쪽)에 때릴 수 있는 적이 하나도 없을 때만** 뒤로 돌아선다.
> "더 가까운 쪽으로 간다"로 만들면 전열의 아군이 새어 나간 적 하나를 쫓아 전선을
> 비우고, 그러면 §3.3 의 구조적 심장(게이트 B16)이 무너진다 — 실측으로 무방벽
> 편성의 잔여 방주 HP 가 기준선의 **72%** 가 됐다 (상한 70%).
> 예외 둘: **`SUPPORT` 는 적을 쫓지 않는다**(힐러가 적진으로 걸어 들어간다),
> **적을 붙들고 있는 `BLOCKER` 는 자리를 지킨다**(스티키 블록이 통째로 풀린다).
> `src/game/logic/pursuit.test.js` 가 전수로 지킨다.

### 3.3 블로킹

```
BLOCKER 유닛만 blockCount(1~3) 를 가진다.
적이 블로커 사거리에 진입 → 블록 슬롯이 남아 있으면 정지, 교전
블록 슬롯 만석 → 적은 통과 (블로커를 무시하고 전진)
FLYING 적은 블로킹되지 않는다.
```

이것이 이 게임의 구조적 심장이다. **탱커 없이 딜러만 편성하면 적이 그냥 걸어서 방주까지 온다.**

### 3.4 방주 HP

| 항목 | 값 |
|---|---|
| 기본 HP | 100 |
| 적이 방주 도달 시 | 적 `breachDamage` 만큼 감소, 적은 소멸 |
| 잡몹 breachDamage | 2–5 |
| 엘리트 | 10–15 |
| 보스 | 즉시 패배 |

별 조건 ②가 "HP 90% 이상"이므로 **잡몹 2–3마리 통과까지는 허용**되는 관대한 설계.

## 4. 지휘관

### 4.1 조작

| 입력 | 동작 |
|---|---|
| 전장 롱프레스 + 드래그 | 지휘관 이동 (목표 지점으로 이동) |
| 레인 라벨 탭 | 해당 레인으로 즉시 이동 |
| 주문 슬롯 탭 | 주문 발동. **대상을 묻지 않는다** — 레인형은 지휘관이 선 레인에 떨어진다 |
| 더블탭 | 대시 (쿨다운 6초, 무적 0.3초) |

**자동 위치 모드**(설정): 지휘관이 "가장 위험한 레인"으로 자동 이동. 방치·캐주얼 유저용. 효율 약 70%.

### 4.2 오라

| 항목 | 값 | 데이터 |
|---|---|---|
| 오라 반경 | **192** | `balance.json:commander.auraRadius` |
| 최대 반경 | **533** — 성소 만렙(242) → 각인 '광역 지휘' 3스택(×1.3) | `commander.auraRadiusMax` |
| 오라 형태 | 지휘관 중심 원. **레인을 가로지른다** (인접 레인 일부 포함) | |
| 시각 표현 | 바닥에 반투명 링 + 오라 내 유닛에 미세 발광 | |

> **★ 이 표의 수치를 여기에 고정하지 않는다** (2026-08-05 정정).
> 오래 **96px / 최대 168px** 이라고 적혀 있었는데 데이터는 그때도 192 였다 —
> 문서만 옛 값에 남아 있었다. 지금은 `data:validate` 가 `auraRadiusMax` 를
> 성소·각인 데이터에서 **계산해 대조**하고, 가이드 화면도 같은 값을 읽는다
> (`logic/guide.js:guideFacts("aura")`). 수치를 바꾸려면 `balance.json` 을 바꾼다.

**역할별 오라 효과** (GDD §4.4 재확인)

| 역할 | 오라 안 | 오라 밖 | 데이터 키 (`balance.json:commander.auraEffects`) |
|---|---|---|---|
| `BLOCKER` | 블록 수 **+1**, 받는 피해 **−20%** | 기본 | `blockBonus` · `damageTakenMult` |
| `MELEE` | **처형** — 남은 HP **12% 이하**의 적을 즉시 처치 | 평타만 | `execThreshold` |
| `RANGED` | **관통 +1** 과 사거리 **+30%** (둘 다) | 평타만 | `pierceBonus` · `rangeMult` |
| `CASTER` | 스킬 쿨다운 **−35%** | 정상 | `cooldownMult` |
| `SUPPORT` | **비활성** | **힐/버프 작동** ← 역발상 | `inverted` |
| `SIEGE` | 한 대마다 적을 균열 쪽으로 **12px** 밀어낸다 | 기본 | `pushPower` |
| `FLYER` | 고도 하강(지상 공격 가능) | 공중만 | `canHitGround` |

> ★★★ **2026-08-05 — 이 표의 절반이 코드에 존재하지 않았다.**
>
> `MELEE` · `RANGED` · `SIEGE` 는 `balance.json` 에서 `special: true` 였다.
> 그 값은 "여기에 무언가 있다"는 표식일 뿐 **무엇인지를 말하지 않으므로 읽는
> 코드를 쓸 수가 없다.** 실제로 아무도 읽지 않았고, 근접·공성 동료는 오라 안팎이
> 완전히 같았다 (원거리는 사거리 배율만 돌고 있었다). `SUPPORT.inverted` 도
> 마찬가지로 死필드였다 — 반전 규칙이 `aura.js` 에 `"SUPPORT"` 문자열로 박혀
> 있어서, 그 값을 `false` 로 바꿔도 게임은 하나도 달라지지 않았다.
>
> 지금은 **효과마다 이름 붙은 수치**이고, `tools/validate-data.mjs` 가
> "선언한 키는 `src/game/logic` 어딘가에서 읽힌다"와 "`special` 금지"를 강제한다.
> `logic/aura.test.js` 는 한 걸음 더 나가 **데이터를 끄면 같은 시드의 전투 결과가
> 달라지는지**를 본다 (`sigils:audit` 과 같은 수법).
>
> ★ `MELEE` 의 셋(넉백/처형/연쇄) 중 **처형**을 골랐다. 넉백은 `SIEGE` 의 칸이고,
> 근접에까지 주면 방벽이 붙든 적의 간격이 매 틱 흔들려 §3.3 의 스티키 블록이
> 풀린다. 연쇄는 레인당 타겟을 하나 더 찾아야 해서 병합 스윕의 O(n+m) 을 깬다.
> 임계 0.12 는 각인 '처형'(0.18 · 역할 무관 · 상시)보다 **낮다** — 그러지 않으면
> 그 각인이 §5.3 이 경고한 "아무 일도 하지 않는 선택지"가 된다.
>
> ★ `SIEGE` 의 "방주 방향 밀어내기"는 **방주에서 멀어지는 쪽**으로 읽는다.
> '오라 안' 칸은 언제나 강화이고, 적을 방주 쪽으로 미는 것은 강화가 아니라 자해다.
> ★★ **방벽이 붙든 적은 밀지 않는다.** 밀면 `blockedBy` 간격이 블로커 사거리를
> 넘어 스티키 블록이 그 자리에서 풀리고, §3.3 의 "용량만큼은 확실히 멈춘다"가
> 무너진다 (2026-08-04 에 고친 "방벽을 간헐적으로 넘어간다"의 재발). 그래서 이
> 효과는 **이미 새어 나간 적**에게만 걸린다 — 공성이 뒤에서 지연시킨다는 그림 그대로다.
>
> ★ `SPECIALIST` 행은 **지웠다.** 그 역할은 2026-08-04 경량화(재배치 시스템 삭제)로
> 사라졌는데 `auraEffects` 에는 `redeployMult` 가 남아 있었다 —
> `logic/roles.js:ROLE_ORDER` 에 없는 역할의 오라 효과는 영원히 발동하지 않는다.
> 검사기가 이제 그 유령을 오류로 잡는다.

> ★★ `FLYER` 행은 2026-08-05까지 **코드에 존재하지 않았다.** `balance.json` 의
> `auraEffects.FLYER.canHitGround` 를 읽는 곳이 없어서 비행 동료 4종은 공중 적이
> 없는 판에서 **한 대도 때리지 않았다** (`engage.js:strikeGround` 가 지금 구현한다).
>
> ⚠ **다만 기하가 이 규칙을 거의 막고 있다.** 공중 레인 `airY=224` 와 레인 y 의
> 수직 거리는 96 / 192 / 288 이고 기본 오라 반경은 192 다:
>
> | 지휘관 레인 | 수직 거리 | 오라가 공중 레인에 닿는 가로 폭 |
> |---|---|---|
> | 0 (위) | 96 | ±166 |
> | 1 (가운데) | 192 | **0 — 사실상 도달 불가** |
> | 2 (아래) | 288 | **도달 불가** |
>
> 즉 지금은 **지휘관이 맨 위 레인에 있을 때만** 비행 동료가 지상을 때린다.
> 장구로 반경을 242 까지 올리면 레인 1 에서도 ±147 이 열린다.
> 이것을 의도로 둘지(= 비행은 위 레인 전용 운용), `airY` 나 `auraRadius` 를 조정할지는
> **설계 결정이므로 데이터를 임의로 바꾸지 않았다.**

**설계 의도:** 지원 유닛의 반전이 "지휘관을 전선에 고정"이라는 단일 최적해를 제거한다. 힐러를 쓰는 편성은 지휘관을 앞에 두고, 힐러를 안 쓰는 편성은 자유롭다 — **편성이 조작 스타일을 결정한다.**

### 4.3 지휘관 생존

- 개인 HP 보유. 적에게 피격됨
- HP 0 → **사망이 아니라 기절 후 방주 귀환, 8초 재출격 대기**
- 대기 중에는 오라가 없으므로 전선이 급격히 약해진다 → 그 자체가 충분한 페널티
- 방주 HP는 감소하지 않는다 (이중 처벌 방지)

### 4.4 지휘관 주문 — **12종 중 4종을 들고 나간다** (2026-08-05)

수치의 정본은 `src/game/data/spells.json`, 규칙은 `src/game/logic/spells.js` 다.
아래 표는 설계 의도를 적은 것이고, **숫자가 다르면 데이터가 맞다.**

| 주문 | 코스트 | 쿨다운 | 대상 | 효과 | 왜 다른 선택인가 |
|---|---|---|---|---|---|
| **균열 낙뢰** | 25 | 3s | 레인 | 술식 광역 42 | 최소 성능이 늘 보장된다 (DEF 무시). 특효도 없다 |
| **치유의 파동** | 35 | 8s | 오라 | 최대 HP 30% 회복 | 위치가 곧 위력 — 오라 밖은 못 받는다 |

| **방주 수리** | 50 | 24s | — | 방주 최대 HP 12% 회복 | 유일하게 패배 조건 자체를 되돌린다 |

**규약**

- **장착 4칸.** HUD 도크가 네 칸이라서가 아니라 **배제가 곧 결정**이기 때문이다
  (설계 결정 1 — 50 로스터 중 6칸과 같은 규약). 강제하는 곳은 화면이 아니라
  `logic/spells.js` 다: `createSpellState(equipped)` · `canCast` · `pickAutoSpell`.
- **가장 싼 4종의 코스트 합 > 균열력 최대치.** 넘지 않으면 4칸이 '무엇을 고를까'가
  아니라 '어느 순서로 누를까'가 된다. `data:validate` 가 강제한다.
- **해금은 확정 지급이다** (절대 규칙 6). 기본 4종은 처음부터, 나머지 8종은
  `unlockStage` 에 적힌 스테이지 첫 클리어에 들어온다 — 지휘관 장구와 같은 규약.
- **레인형은 대상을 묻지 않는다.** 지휘관이 **서 있는 레인**에 떨어진다. 조준이
  곧 위치 선정이라 이 게임의 핵심 조작과 같은 축이다.
- **상성 세 축이 전부 대표된다** (물리 · 술식 · 신성). `data:validate` 가 강제한다.

> ⛔ **'시간 정지'와 '소집'은 만들지 않았다.** 전역 시간 배율과 위치 순간이동은
> 결정론·정렬 배열 불변식을 건드린다 (`state.js` 의 x 오름차순 병합 스윕).
> 12종은 그 둘 없이 채웠다.

## 5. 웨이브와 템포

### 5.1 웨이브 구조

```
[배치 5초] → W1 → W2 → W3 → [각인 3지선다] → W4 → W5 → W6 → [각인] → ... → 보스/최종
```

- 일반 스테이지 **9–15 웨이브**, 목표 전투 시간 **90–150초**
- 보스 스테이지 **12–18 웨이브 + 보스**, **180–240초**
- 웨이브 간격 6–10초. 다음 웨이브 구성이 **상단에 미리 표시**된다 (태그 아이콘)

### 5.2 템포 시프트 — 균열 확장

**전체 웨이브의 60% 지점**에서 발동:

| 변화 | 값 |
|---|---|
| 마나 재생 | 6.0 → **12.0 / 초** |
| 동료 소환 쿨다운 | **−40%** |
| 적 스폰 밀도 | **×1.6** |
| 엘리트 | 등장 시작 |
| 연출 | 화면 색보정 전환(보라 틴트), BGM 퍼커션 레이어 추가, 균열 스프라이트 확대, 카메라 셰이크 0.4s |

**3막 구조 확보:** 1막(경제 구축, 신중한 배치) → 2막(스윙, 자원 폭발) → 3막(해결, 총력전).
첫 45–60초가 의무적 거북 구간이 되지 않도록 **1막에도 처치 환급이 의미 있는 밀도**로 적을 배치한다.

### 5.3 각인 드래프트

| 항목 | 값 |
|---|---|
| 등장 주기 | **3웨이브마다** |
| 선택지 | **3개** (기록보관소 업그레이드로 4개까지) |
| 리롤 | 기본 1회 / 스테이지, 업그레이드로 3회까지 |
| 일반 스테이지 픽 수 | **4–6** |
| 기억의 탑 픽 수 | **12–18** |
| 게임 정지 여부 | **정지한다.** 3초 내 미선택 시 자동 선택 (방치 대응) |

> ★★ **각인이 언제부터 적용되는가** (2026-08-05 확정 — 사용자 제보 "철벽·대공탄이
> 적용되지 않는 것 같다"). 이 규칙은 훅이 아니라 **연산(op)** 이 정한다.
>
> | 종류 | 적용 시점 | 왜 |
> |---|---|---|
> | **능력을 여는 각인** (`addRoleBlock` 철벽 · `addTag` 대공탄) | **이미 나와 있는 아군에게도 즉시** | 그 각인은 *지금 오는 위협*을 보고 고르는 것이다. 비행 웨이브를 보고 대공탄을 골랐는데 그때 서 있던 궁수가 끝까지 공중에 못 닿으면, 고른 사람에게 아무 일도 하지 않는다. 설명도 "**모든** 방벽/원거리 동료"다 |
> | **수치를 미는 각인** (공격력·체력·공속·투사체) | **이후 소환분부터** | 일찍 고르는 판단이 의미를 갖는다. 소급시키면 게이트 B16(방벽 필수성)이 실측으로 무너진다 — 무방벽 잔여 방주 HP 48.9% → 72.0% (상한 70%) |
>
> `logic/sigils.js:RETROACTIVE_OPS` 가 목록이고 `logic/sigils.effect.test.js` 가 전수로 지킨다.
>
> ★ **`maxStacks` 는 거짓말을 하면 안 된다.** 같은 훅을 두 번 등록해도 결과가 같은
> 연산(임계값·설정형)에 `maxStacks > 1` 을 주면, 드래프트에 다시 뜨는 그 각인은
> **아무 일도 하지 않는 선택지**가 된다. '처형'(임계 18%)이 그랬다.

## 6. 전투 모드

### 6.1 격퇴 (Assault) — 기본형

모든 웨이브를 격퇴. 월드당 14 스테이지.

### 6.2 돌파 (Breach)

**균열 자체를 파괴**한다. 균열 HP가 존재하고, 아군 유닛이 x=592에 도달해 공격해야 한다.
- 동료가 **전진**해야 하므로 블로커 중심 편성이 불리해지고 `SIEGE`·`MELEE` 가치 상승
- 제한 시간 존재 (초과 시 패배)
- 월드당 2 스테이지

### 6.3 호위 (Escort)

이동하는 보급 수레(HP 보유)를 우측으로 호위. 수레가 균열에 도달하면 승리.
- 수레는 자동으로 전진하되, **아군이 근처에 있어야 이동**한다 (전선을 끌고 가야 함)
- 지휘관 오라가 수레 이동속도를 올린다 → 지휘관을 전방에 강제
- 월드당 2 스테이지

### 6.4 버티기 (Endure)

**동료 소환 불가.** 시작 시 주어진 고정 편성으로 제한 시간 생존.
- 각인 드래프트만이 유일한 성장 수단 → 순수 로그라이트 체험
- 팔라독의 "규칙을 깨는 변주 스테이지"의 계승
- 월드당 1 스테이지

### 6.5 보스 (Nemesis)

단일 대형 보스 + 주기적 소환수. 보스는 **페이즈 3개**를 가진다.
- 페이즈 전환 시 태그가 바뀐다 (예: P1 `ARMORED` → P2 `WARDED` → P3 `FLYING`)
- **한 가지 데미지 타입만으로는 클리어할 수 없게** 만드는 장치
- 월드당 1 스테이지 (스테이지 20)
