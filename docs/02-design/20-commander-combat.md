## 0. 왜 이 문서가 필요한가

GDD §3 은 지휘관을 이렇게 규정한다:

> 방주 밖으로 **직접 걸어 나가 싸울 수 있는** 유일한 존재

그런데 §4.4 의 지휘관 스탯 목록은 이렇다:

> 오라 반경 / 오라 강도 / 이동속도 / 개인 HP / 주문 슬롯 4개

**"싸울 수 있다"고 써 놓고 싸우는 수단이 없었다.** 지휘관은 걸어 다니며 오라를
투사하고, 균열력으로 주문 4종을 쓰고, 맞으면 기절한다. 공격은 하지 않는다.
플레이어 캐릭터가 전장 한가운데 서서 **아무것도 하지 않는 상태**가 기본값이었다.

이 문서는 그 구멍을 메우되, **이 게임을 정의하는 설계 결정 5가지**(CLAUDE.md)를
하나도 깨지 않는 방법을 정한다.

## 1. 깨면 안 되는 것 — 설계 제약

평타를 붙이는 일은 쉽다. 어렵고 중요한 것은 **붙여도 게임이 망가지지 않는 것**이다.
아래 넷은 협상 대상이 아니다.

| # | 제약 | 출처 | 평타가 이것을 깨는 방식 |
|---|---|---|---|
| C1 | **지휘관 오라가 실력 천장이다** | CLAUDE.md 설계결정 3 | 평타가 세면 실력 천장이 "오라 운영"에서 "지휘관 조준"으로 옮겨간다 |
| C2 | **벽은 편성 퍼즐이지 경제 벽이 아니다** | 설계결정 5 · 게이트 B4 | 지휘관이 만능딜을 하면 편성이 틀려도 뚫린다 — 퍼즐이 사라진다 |
| C3 | **중앙에 세워만 둬도 약 70% 효율** | GDD §4.4 "대충 플레이 허용선" | 평타가 조준·이동을 요구하면 방치 플레이가 70% 아래로 떨어진다 |
| C4 | **확률형 요소 0개 · logic/ 은 순수** | 절대규칙 1·6 | 난수 조준·난수 쿨다운은 결정론과 밸런스 자동검증을 죽인다 |

### 결론 — 설계 방향

> **평타는 "딜 수단"이 아니라 "지휘관을 앞에 세우고 싶게 만드는 미끼"다.**

수치로 이기게 하지 않는다. 대신 **이미 존재하는 위치 긴장**(오라 안 ↔ 밖)에
보상 한 겹을 얹어, 플레이어가 스스로 위험한 자리로 나가게 만든다.

## 2. 규칙

### 2.1 평타 (구현됨)

| 항목 | 규칙 | 이유 |
|---|---|---|
| 발동 | **자동**. 조준·버튼 없음 | C3 — 방치 효율을 지킨다. 조작을 늘리지 않는다 (GDD §8 "필수 조작 3가지만") |
| 대상 | **지휘관이 선 레인의 지상 적** 중 사거리 안에서 **방주에 가장 가까운 것** | 결정론(C4). "가장 급한 적"이라는 직관과도 일치한다 |
| 공중 | **때리지 않는다** | C2 — 1-6 "공중 — 방벽을 무시한다"가 편성 퍼즐로 남아야 한다. 지휘관이 공중을 때리면 대공 편성이 선택이 아니게 된다 |
| 피해 타입 | **물리(physical)** | C2 — 중장갑(1-5)을 지휘관 혼자 못 뚫는다. DEF 를 그대로 맞는 유일한 타입이다 |
| 기절 중 | 발동하지 않음 | 기절 페널티가 "오라 상실"만이 아니게 된다 |
| 난수 | 조준·간격에 없음. 크리티컬만 기존 `s.rng.combat` 공용 굴림 | C4 |

**사거리는 오라 반경보다 짧다.** 이것이 이 설계의 핵심 한 줄이다:

```
평타 사거리(140) < 오라 반경(192)
```

지휘관이 평타를 넣으려면 **오라의 앞쪽 절반을 적에게 내주는 위치**까지 나가야 한다.
그러면 자동으로:

- **SUPPORT 가 죽는다** — 지원 유닛은 오라 *밖*에서만 작동한다(GDD §4.4). 지휘관이
  앞으로 나가면 후방 지원이 오라에 삼켜져 힐이 끊긴다.
- **지휘관이 맞기 시작한다** — 기절하면 8초간 오라가 통째로 사라진다.

즉 **평타를 넣는 행위 자체가 비용을 지불한다.** 딜을 얻고 힐과 안전을 잃는다.
C1 이 요구하는 "오라 운영이 실력 천장"이 오히려 **강화**된다 — 판단할 것이 하나 늘었다.

### 2.2 스킬 (이미 있음 — 이 문서의 범위 밖)

지휘관 주문 4종은 `data/spells.json` + `logic/spells.js` 로 **이미 구현되어 있다.**
균열력을 쓰고, 쿨다운이 있고, HUD 에 버튼이 있다. 새로 만들 것이 없다.

> ⚠ 한때 이 버튼들은 **죽은 UI** 였다 (하드코딩 배열 + `disabled`, 차감 코드 0곳).
> 지금은 살아 있다. 되살린 경위는 `hud/BattleHud.jsx:RiftBar` 주석 참조.

### 2.3 적이 지휘관을 노린다 (2026-08-05 구현)

> **§2.1 의 마지막 줄("그러면 지휘관이 맞는다")이 4개월 동안 거짓말이었다.**

지휘관은 `lanes[].allies` 에 들어가지 않아 `engage.js:nearestTarget` 의 후보가
아니었고, 지휘관 HP 를 깎는 코드는 **보스 슬램뿐**이었다(`boss.js`). 즉 위에서
설계한 비용 구조의 절반 — "앞으로 나가면 맞는다" — 이 존재하지 않았다.
평타는 힐만 잃고 안전은 잃지 않는, 사실상 **공짜 DPS** 였다.

#### 규칙 — 적은 지휘관을 맨 마지막에 본다

| 항목 | 규칙 | 이유 |
|---|---|---|
| 우선순위 | 자기 **사거리 안에 동료(아군 유닛)가 하나라도 있으면** 그를 때린다. **하나도 없을 때에만** 지휘관을 노린다 | 아래 참조 |
| 레인 | **같은 지상 레인**만 | 지휘관은 한 줄에 서 있다. 오라만 레인을 가로지른다 |
| 공중 | 공중 적은 지휘관을 **때리지 않는다** | C2 — 지휘관이 공중을 못 때리는 것과 대칭. 한쪽만 두면 1-6 "공중"이 편성 퍼즐이 아니라 지휘관 문제가 된다 |
| 원거리 적 | 발사체를 쏘고, 그 탄이 지휘관에게 **맞는다** (`projectiles.js`) | 지휘관은 레인 배열에 없어 명중 루프가 따로 보지 않으면 탄이 그대로 통과한다 — "노리는데 안 맞는" 죽은 규칙이 된다 |
| 탄 우선순위 | 동료를 아무도 못 맞힌 탄만 지휘관을 맞힌다 | 지휘관이 동료의 탄을 가로채면 "앞에 세워두면 탱커"가 되어 설계결정 5 가 무너진다 |
| 난수 | 없다. 크리티컬도 굴리지 않는다 | C4 — `s.rng.combat` 을 한 번 더 당기면 그 뒤 모든 굴림이 밀려 결정론 비교(B1)가 무의미해진다 |

**"가장 가까운 것"으로 만들면 안 된다.** 지휘관이 전선에 서는 순간 그 레인의
무리 전체가 그에게 몰린다 — 미끼가 아니라 즉사이고, C3(중앙에 세워만 둬도 70%)도
같이 죽는다.

"동료 다음" 규칙은 §2.1 의 부등식을 **그대로 뒤집어** 준다:

- 동료 라인 **뒤**(= 오라를 온전히 씌운 자리)에 있으면, 적의 사거리 안에는 언제나
  동료가 먼저 있다 → 지휘관은 후보조차 아니다. **방치 효율이 유지된다.**
- 평타 사거리(140)까지 나가면 지휘관이 동료보다 앞에 선다 → 전선 앞의 적들에게는
  **지휘관이 유일한 표적**이 된다.

즉 위험이 위치에서 **연속적으로** 자란다. 앞으로 나갈수록 "동료는 사거리 밖이고
지휘관은 사거리 안"인 띠가 넓어지고, 그만큼 많은 적이 지휘관을 본다.

**지휘관은 벽이 되지 않는다.** 적은 `movement.js` 에서 **BLOCKER 에게만** 멈추고
교전 중에도 계속 걸어간다(게이트 B16). 지휘관을 앞에 세워도 진군이 늦어지지 않으므로
"지휘관 = 무한 방벽" 이라는 우회로가 생기지 않는다 — 그것이 생기면 설계결정 5
(벽은 편성 퍼즐)가 무너진다.

**대신 적의 공격 하나를 가져간다.** 지휘관을 때린 적은 그 틱에 쿨다운을 쓴다.
이것이 "미끼"의 문자 그대로의 뜻이다 — 앞에 나가면 동료가 맞을 몇 대를 대신 받는다.

#### 피해에는 상한이 있다

`balance.json:combat.enemyHitCommanderHpRatio` = **0.08** (최소 12방).

보스 슬램이 이미 부딪힌 벽과 **완전히 같은 문제**다 — 지휘관 HP 는 600 고정인데
일반 적 ATK 는 1-1 의 10 에서 5-20 의 342,133 까지 간다(실측, 34,000배). 배율
하나로는 절대 맞출 수 없으므로 상한을 **HP 비율**로 둔다. 슬램(0.3 · 최소 4방)보다
훨씬 무른 이유는 빈도다: 슬램은 7~10초에 한 번 예고를 달고 오지만 일반 적은
1초에 한 대씩, 그것도 여러 마리가 동시에 때린다.

상한 적용 · HP 차감 · 기절 신호 · 피격 이벤트는 **`logic/commanderHit.js:damageCommander`
하나**가 맡는다. 보스 슬램도 이제 같은 함수를 쓴다 — 같은 규칙을 두 곳에 적으면
반드시 갈라진다.

**지휘관에게는 방어 스탯이 없다** (DEF · RES · 태그 · 실드 전부). 만들어 주는 것은
성장 축을 하나 더 여는 일이고(범위 절삭 §2), DEF 0 · RES 0 이면 `computeDamage` 는
`atk` 를 그대로 돌려주므로 지나도 결과가 같다.

#### 실측 (`SEEDS=12` · 추천 편성 · 자동 조작)

| 스테이지 | 기절/판 | 피격/판 | 전투 중 최저 HP |
|---|---|---|---|
| 1-1 | 0.00 | 2.3 | 90% |
| 1-9 | 0.17 | 5.8 | 0% |
| 2-5 | 0.17 | 11.4 | 0% |
| 2-10 | 0.00 | 10.0 | 4% |
| 5-20 | 0.08 | 4.9 | 0% |

자동 조작(`autoPlay.js` 는 지휘관을 `front - 140`, 즉 평타 사거리에 세운다)에서
**6~12판에 한 번 기절**한다. 대가는 존재하되 파탄은 아니다 — "회피는 잘하면
이득이어야지 못하면 파탄이면 안 된다"(슬램 주석)와 같은 기준이다.

#### 틱 예산

`tryHitCommander` 는 `nearestTarget` 이 **빈손일 때만** 불린다. 교전 중인 적
(대다수)에게는 비용이 0 이고, 나머지도 비교 두 번이다. "매 틱 전 적이 지휘관
거리를 잰다"는 O(n) 을 만들지 않는다.

## 3. 데이터 (절대규칙 4)

`src/game/data/balance.json`:

```jsonc
"commander": {
  "auraRadius": 192,
  ...
  "attack": {
    "damage": 18,       // 스테이지가 올라도 고정 — 후반에는 존재감이 사라진다 (의도)
    "intervalMs": 900,
    "range": 140,       // ★ auraRadius(192) 보다 반드시 짧다
    "dmgType": "physical"
  }
}
```

**`damage` 를 레벨로 올리지 않는다.** 초반에는 체감되고 후반에는 무의미해지는 것이
의도다 — 후반의 답은 언제나 편성이어야 한다(C2). 지휘관 성장은 계속 **오라 반경 ·
개인 HP** 로만 간다.

**`range < auraRadius` 는 규약이다.** 이 부등식이 깨지면 §2.1 의 비용 구조가
통째로 사라지므로, `data:validate` 가 검사한다.

## 4. 밸런스 영향과 검증

평타는 **모든 스테이지에 공짜 DPS 를 더한다.** 반드시 재검증해야 한다.

| 하네스 | 무엇을 지키는가 | 결과 |
|---|---|---|
| `npm run balance:check` | 13항 하드/소프트 게이트 (300시드) | **13/13 통과** |
| `npm run economy` | 무과금 파워 커브 | 통과 |
| `npm run playthrough` | 신규 계정 100 스테이지 완주 | 완주 |
| `npm run sigils:audit` | 각인 18종이 여전히 결과를 바꾸는가 | 통과 |

특히 **게이트 B4**(현재 파워 + 올바른 편성 = 클리어 가능)가 지켜지는지가 C2 의
기계적 증명이다. 평타가 세서 *틀린* 편성으로도 뚫리기 시작하면 B4 가 아니라
**B2(적정 승률)** 가 먼저 위로 튄다 — 그때는 `damage` 를 내린다.

## 5. 연출

절대규칙 8(풀링) · 아트 제약(유닛에 공격 애니메이션 없음)을 따른다.

- 지휘관 스프라이트는 **아이들 루프만** 있다 → 공격 모션은 **트윈**(돌진·리코일)으로 만든다.
- 명중 지점에 `EffectSystem` 이펙트 1회 + 기존 `DamageTextPool` 숫자.
- 새 이벤트 `EV.COMMANDER_ATTACK` (27) 을 씬이 받아 연출한다.
  번호는 **덧붙이기만** 한다 (`events.js` 주석 참조).

**피격(§2.3)은 새 이벤트를 만들지 않는다.** 기존 `EV.DAMAGE` 에 **예약 id**
`COMMANDER_ID = -1` 을 실어 보낸다 — 엔티티 id 는 1 부터 세므로 영영 충돌하지 않는다.
`BattleScene.onDamage` 가 그 id 를 갈라내 `CommanderPresenter.playHurt()`(흰 틴트
70ms · `presenters.json:commander.hurt`) + 데미지 숫자로 보낸다.

> ⚠ 이 갈래가 없으면 적이 지휘관을 때리는 것이 **화면에서 완전히 무음**이다.
> 지휘관은 `s.actives` 에 없어서 `findEntity` 도 스프라이트 맵도 그를 모르고,
> 플레이어가 볼 수 있는 것은 갑자기 뜨는 "재출격 8" 뿐이다.

**아직 없는 것: 지휘관 HP 표시.** HUD 에는 지휘관 체력 게이지가 없다
(`hud/BattleHud.jsx` 에는 `commander_down` 문구뿐). §2.3 로 지휘관이 실제로
닳기 시작했으므로, "앞으로 나가면 위험하다"를 **숫자로** 읽을 수단이 필요하다.

## 6. 하지 않기로 한 것
