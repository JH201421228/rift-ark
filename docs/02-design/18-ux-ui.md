# 18. UX / UI — 가로형 모바일

> 디자인 해상도 **1280 × 720**, `Phaser.Scale.FIT`, 가로 고정.
> UI는 **React DOM 오버레이**가 담당하고 Phaser는 월드 앵커 요소만 그린다 (`03-tech/20-architecture.md`).

> ## ⚠ 2026-08-04 범위 절삭 — 화면이 16 → 6 이 됐다
>
> **남은 화면:** 방주 · 출격 · 편성 · 동료 · 설정 · 전투(+결과 오버레이).
> 동료 화면은 탭 셋이다 — **성장 · 영입 · 별 트리**.
>
> ★ **Phaser 캔버스는 UI 뒤에 아무것도 그리지 않는다** (2026-08-04).
> 방주 씬이 그리던 거점 단면도는 불투명 UI 뒤에서 알아볼 수 없는 도형으로만 보였다.
> 배경을 되살린다면 UI 뒤가 아니라 **전용 전체화면 뷰**여야 한다.
> **탭바는 5칸**이다 (방주 · 출격 · 편성 · 동료 · 설정).
> 상점 · 일일 · 패스 · 도감 · 던전 · 탑 · 시험 · 확률공개 · 가챠 연출 · 계측 대시보드는 삭제.

## 1. 화면 규격

### 1.1 해상도와 안전 영역

| 항목 | 값 |
|---|---|
| 디자인 해상도 | **1280 × 720** (16:9) |
| 스케일 모드 | `Phaser.Scale.FIT` + `CENTER_BOTH` |
| 최소 | 960 × 540 |
| 최대 | 2560 × 1440 |
| **UI 안전 영역** | 중앙 **1136 × 720** (좌우 각 72px 여백) |

**백버퍼는 기기와 무관하게 항상 1280×720 이다.** `FIT` + 고정 width/height 조합이므로 캔버스 내부 해상도가 변하지 않고 브라우저가 업스케일한다. 즉 필레이트가 기기별로 변하지 않는다 (921,600px × 60fps ≈ 55Mpx/s).

**실측 스케일**

| 기기 | 뷰포트 | 배율 | 레터박스 |
|---|---|---|---|
| 20:9 안드로이드 | 2400 × 1080 | 1.50 | 좌우 각 240px |
| 16:9 | 1920 × 1080 | 1.50 | 없음 |
| iPhone 15 Pro | 2556 × 1179 | 1.64 | 좌우 각 230px |
| iPad 4:3 | 1024 × 768 | 0.80 | 상하 각 96px |

**대응 화면비**

| 기기 | 비율 | 결과 |
|---|---|---|
| 일반 스마트폰 | 16:9 | 정확히 일치 |
| 최신 안드로이드/아이폰 | 19.5:9 ~ 21:9 | 좌우에 레터박스. **노치/다이내믹아일랜드가 레터박스에 흡수됨** |
| 태블릿 | 4:3 | 상하 레터박스 |

**핵심 결정: 캔버스는 풀블리드로 두고 세이프에어리어 패딩은 React 오버레이에만 적용한다.**
FIT의 레터박스 바가 노치를 흡수하므로 게임플레이 영역은 항상 온전하다.

```css
#ui-overlay {
  position: absolute; inset: 0;
  pointer-events: none;
  padding: env(safe-area-inset-top)  env(safe-area-inset-right)
           env(safe-area-inset-bottom) env(safe-area-inset-left);
}
#ui-overlay .interactive { pointer-events: auto; }
```

### 1.2 터치 타깃

| 요소 | 최소 크기 (CSS px, 실제 기기 기준) |
|---|---|
| 주 액션 (동료 슬롯, 주문) | **48 × 48** |
| 보조 버튼 | 40 × 40 |
| 목록 항목 | 높이 44 |
| 인접 타깃 간 간격 | ≥ 8 |

디자인 해상도 1280×720 에서 1 디자인px ≈ 실제 기기 1–1.6 CSS px 이므로, **캔버스 내 UI는 최소 40 디자인px** 로 잡는다.

### 1.3 한글 대응

> **한글은 라틴 문자의 약 2배 폭을 차지한다. 1일차부터 한국어 문자열로 UI를 테스트한다.** 다른 어떤 현지화 이슈보다 많은 게임이 여기서 깨진다.

- 모든 텍스트 컨테이너는 **한국어 최대 길이 + 20%** 로 설계
- **폰트 확정: 물마루 모노 (Mulmaru Mono)** — 한글 음절 11,172자 전체 포함, unitsPerEm 192의 픽셀 그리드 폰트, 98KB. `asset/fonts/base_font.woff2`
  - **모노스페이스**이므로 HUD 수치·타이머·코스트가 흔들리지 않는다 (별도 `tabular-nums` 불필요)
  - 픽셀 그리드 폰트이므로 **정수 크기로만 렌더**한다. 비정수 크기는 글리프가 뭉개진다
  - 1280×720 에서 실제로 글리프가 픽셀 그리드에 안착하는 것을 확인했다 (640×360 에서는 캔버스 업스케일 때문에 흐릿했다)
- **본문에 픽셀 폰트를 강제하지 않는다.** 헤드라인·수치·버튼·HUD 는 물마루 모노, **긴 설명문(도감 · 각인 설명 · 스토리)은 시스템 산세리프**(Pretendard/나눔고딕)로. 가독성이 스타일보다 우선한다
- 숫자는 **고정폭(tabular-nums)** — HUD 카운터가 흔들리지 않게

### 2.1 동료 슬롯

| 상태 | 표현 |
|---|---|
| 사용 가능 | 컬러, 코스트 흰색 |
| 마나 부족 | 60% 어둡게, 코스트 빨강 |
| 쿨다운 | 방사형 마스크 오버레이 |
| **코스트 상승 중** | 코스트 옆 **▲** + 상승분 표시 (`26 ▲+5`) |
| 레인 선택 중 | 슬롯에서 레인으로 가이드 라인 |

**소환 입력 2가지 (설정으로 전환, 기본 = 원터치)**

| 모드 | 동작 |
|---|---|
| **원터치 (기본)** | 탭 → 가장 비어 있는 레인에 자동 배치. 캐주얼 접근성 |
| **정밀 배치** | 슬롯을 누른 채 전장으로 드래그 → 레인 하이라이트 → 놓으면 배치 |

### 2.2 지휘관 조작

| 입력 | 동작 |
|---|---|
| 전장 롱프레스 + 드래그 | 지휘관 이동 |
| 레인 라벨(좌측 가장자리) 탭 | 해당 레인으로 즉시 이동 |
| 더블탭 | 대시 (쿨다운 6s) |
| 주문 슬롯 탭 | 발동. 타겟형은 탭 후 위치 지정 (조준 링 표시) |

**자동 위치 토글**을 HUD에 상시 노출한다. 방치·캐주얼 유저가 언제든 켤 수 있어야 한다.

### 2.3 적 정보 가독성 — 상성이 보여야 상성이다

**모든 적 위에 태그 아이콘을 상시 표시한다.**

```
       [🛡][✈]        ← ARMORED + FLYING
        ▓▓▓▓░         ← HP 바
         👾           ← 스프라이트
```

- 태그 아이콘 8×8px, 최대 3개 표시 (초과 시 "+n")
- 아이콘은 `icons/Free - Raven Fantasy Icons` 에서 배정, **색상으로도 구분** (색맹 대응: 형태로도 구분)
- **내 편성이 이 태그에 취약하면 아이콘이 붉게 점멸** — 즉각적 피드백
- 롱프레스 → 적 상세 팝업 (스탯 전문, 도감 링크)

### 2.4 데미지 표현 (혁신 15 — 완전 투명성)

| 요소 | 표현 |
|---|---|
| 데미지 숫자 | 타입별 색상 (물리 흰색 / 술식 청색 / 신성 금색) |
| 크리티컬 | 크기 1.4배 + 흔들림 |
| **무효화 수준** (최소 피해 10%) | **"저항!"** 텍스트 + 회색 숫자 ← 상성 실패를 명확히 알린다 |
| 특효 | **"약점!"** + 확대 |
| 힐 | 초록 + `+` |

**설정에서 데미지 숫자 밀도 조절 가능** (전부 / 큰 것만 / 끄기). 저사양 기기에서는 자동으로 "큰 것만".

### 2.5 각인 드래프트 UI

전투를 정지하고 전체 화면으로:

```
┌──────────── 균열 각인 선택 ────────────┐
│                                        │
│  ┌────────┐ ┌────────┐ ┌────────┐     │
│  │ 관통화살│ │ 오라냉기│ │망자의세금│    │
│  │        │ │        │ │  ⚠대가  │    │
│  │원거리가 │ │오라 내 │ │처치시   │    │
│  │2체 관통│ │적 −25% │ │마나+4  │    │
│  │        │ │        │ │HP −8%  │    │
│  │  ✨반응 │ │  ✨반응 │ │        │    │
│  └────────┘ └────────┘ └────────┘     │
│                                        │
│         [🔄 리롤 1회 남음]              │
│   전투는 선택할 때까지 멈춰 있습니다      │
└────────────────────────────────────────┘
```

- **`✨반응` 배지**: 이 각인이 현재 보유 각인과 진화 조합을 이룰 수 있음을 암시. **어떤 조합인지는 알려주지 않는다** → 발견의 즐거움 + 커뮤니티 생성
- **대가형 각인은 `⚠` 로 명확히 표기.** 숨기면 다크 패턴이다
- **수동 플레이에는 제한 시간이 없다** (2026-08-02 변경)
  - 이전에는 3초 카운트다운 후 자동 선택이었다. 각인은 이 게임의 로그라이트
    축이고 조합·진화를 따져 보는 것이 재미의 본체인데, 카운트다운이 그 판단을
    재촉해 **"아무거나 고르기"로 만들었다.**
  - 드래프트 중 시뮬은 완전히 정지한다(`phase: 'draft'`). 기다려도 손해가 없으므로
    제한 시간에 기능적 근거도 없다.
  - **자동 선택은 오토 플레이일 때만 남긴다** — 방치 중에는 드래프트가 진행을
    영원히 막아서는 안 된다.

```

                    │  스플래시   │
                    └──────┬──────┘
                           ↓
        ┌──────────── 타이틀 (`/`) ────────────┐

     ┌──────────────── 방주 (홈) ────────────────┐
     │      [방주] [출격] [편성] [동료] [설정]    │
     └──┬────────┬─────┬──────────────────────┬──┘
        ↓        ↓     ↓                      ↓
    스테이지    편성   동료                  설정
     선택      구성  성장·영입           │├ 사운드
        ↓                                │├ 그래픽 품질
    스테이지 프리뷰 ──→ 전투 ──→ 결과     │├ 조작 방식
                        ↑        │        │├ 접근성
                        └────────┘        │├ 계정
                        (재도전)          │└ 라이선스 표기
```

**타이틀이 먼저다** (2026-08-04). 슬롯을 고르기 전에는 게임 안이 아니므로
**`/` 에서는 탭 바를 띄우지 않는다.** 배경은 codex 키아트 (`assets/title/title-bg.png`).

**방주(홈)가 허브다.** 하단 탭 **5개**는 언제나 1탭 거리 — 아홉이던 시절
(일일·패스·도감·상점) 가로 모드에서 탭 하나당 폭이 44px 터치 타깃 근처까지 내려갔고,
무엇보다 그 넷은 **전투로 가는 길이 아니었다** (`34-scope-cut.md`).
**[출격] 버튼이 가장 크다** — 유저가 가장 자주 누르는 버튼이 가장 크고 엄지 도달 범위(가로 모드 기준 화면 우하단)에 있다.

### 3.0 ~~탭 점진 공개~~ — 철회됨 (2026-08-04)

> ⛔ **튜토리얼과 함께 삭제됐다.** 탭은 **언제나 다섯**이고 진행도로 잠그지 않는다.
> 아래 표는 그때 무엇을 지키려 했는지의 기록이다 — 되살린다면 마지막 줄
> ("`ftue.done` 이면 무조건 전부 보인다")이 그 핵심이었다.

| 규칙 | 이유 |
|---|---|
| **`ftue.done` 이면 무조건 전부 보인다** | 구버전 세이브·스킵·손상 등 어떤 경위로 해금 목록이 비어도 탭이 영영 사라지지 않는다. **튜토리얼 UI 가 본 게임을 잠글 수 있으면 그것은 튜토리얼이 아니다** |
| 지금 보고 있는 화면의 탭은 잠그지 않는다 | 현재 위치가 사라지면 길을 잃는다 |
| 방주 · 설정에는 자물쇠가 없다 | 시작 화면과 탈출구다 |
| 판정은 **스토어**(`isFtueUnlocked`)에 묻는다 | 화면이 `highestStage` 로 직접 판정하면 스킵한 계정과 완주한 계정의 해금 시점이 화면마다 갈린다 |

> 검사: `appShell.test.js` 가 **어떤 조건으로도 탭을 잠그지 않는지**를 본다.

### 3.0.1 가이드 오버레이 — 다시 볼 수 있는 설명 (2026-08-04)

|---|---|
| **라우트를 만들지 않는다** (모달) | 도움말은 보던 화면 위에 잠깐 뜨는 것이 맞고, 라우트를 늘리면 탭바·도달 그래프·뒤로가기가 전부 따라온다 |
| **본문 문장에 수치를 적지 않는다** | 마나 회복량·시설 효과·영입가는 `guideFacts()` 가 데이터에서 그때그때 읽어 "지금 적용 중인 값" 표로 만든다. 문장에 숫자를 박으면 밸런스를 고친 다음 날부터 가이드가 거짓말을 시작한다 (절대 규칙 4) |
| `**강조**` 만 지원한다 | 마크다운 파서도 `dangerouslySetInnerHTML` 도 쓰지 않는다 — 문자열을 조각내 배열로 렌더한다 |

> 검증: `data:validate` 의 가이드 절(빈 본문 · 알 수 없는 fact · 값이 안 나오는 표 ·
> **본문에 박힌 수치**)과 `src/game/logic/guide.test.js`.

### 4.1 동료 > 성장 — 좌 목록 / 우 상세 (2026-08-05)

```
┌─────────────────────────────────────────────────────┐
│ 동료  [?]  [성장][영입][별 트리]           골드 340 │
├──────────────────────┬──────────────────────────────┤
│ 보유 50종            │ [그림] 이름                  │
│ ┌──┬──┬──┬──┬──┐    │        등급·역할·타입·코스트 │
│ │  │  │  │  │  │    │        [대공/지상만]         │ ← 고정
│ ├──┼──┼──┼──┼──┤    ├──────────────────────────────┤
│ │  │  │  │  │  │    │ 서사 / 태그 / 수치 표        │ ← 스크롤
│ └──┴──┴──┴──┴──┘    ├──────────────────────────────┤

```

**출격 화면(§3, `StagePreview.module.css:.layout`)과 같은 관습이다** — 바깥은
스크롤하지 않고 **각 칸이 자기 안에서만** 스크롤한다. 같은 게임에서 두 화면이
서로 다른 규칙으로 움직이면 그 자체가 배워야 할 비용이다.

- **`.body` 를 쓰지 않는다.** 그 클래스는 폭이 모자라면 칸을 아래로 접고(방주·
  별 트리가 그 규약에 기대고 있다) 자신이 통째로 스크롤한다. 성장 탭에 그것을 쓰면
  폰 가로(915×412)에서 상세가 목록 **아래로** 내려가 레벨업 버튼을 보려면 목록
  전체를 지나쳐야 한다. **목록과 상세는 동시에 보여야** 고르는 행위가 성립한다.
- **상세의 머리와 발은 고정이다.** 세로 412px 에서 본문이 길어졌을 때 레벨업
  버튼이 스크롤 밖으로 밀리면, 이 탭에서 할 수 있는 유일한 행동이 사라진다.
- **선택이 없으면 첫 번째를 고른다.** 빈 패널은 고장으로 읽힌다.

### 4.2 동료 > 영입 — 좌 목록 / 우 상세 + [영입한다] (2026-08-05)

```
┌─────────────────────────────────────────────────────┐
│ 동료  [?]  [성장][영입][별 트리]        골드 60,000 │
├──────────────────────┬──────────────────────────────┤
│ 영입 1/40종          │ [그림] 이름                  │
│ · 확률이 없습니다    │        등급·역할·타입·코스트 │ ← 고정
│ · 확정 지급은 여기   │        [대공] [보유 중]      │
│   없습니다           ├──────────────────────────────┤
│ ┌──┬──┬──┬──┐        │ 서사 / 태그 / 수치 표        │ ← 스크롤
│ │  │  │  │  │        ├──────────────────────────────┤
│ └──┴──┴──┴──┘        │ 영입가 2,500     [영입한다]  │ ← 고정
│      (스크롤)        │ · 골드가 2,490 부족합니다 …  │
└──────────────────────┴──────────────────────────────┘
```

**§4.1 과 같은 클래스를 쓴다** (`.split` / `.splitPane` / `.detailPane` /
`.detailScroll` / `.detailFoot`). 실측 폭은 세 화면이 모두 같다 — 915×412 에서
443.5 / 443.5, 1280×720 에서 620 / 620.

- **카드 탭은 고르기이지 사기가 아니다.** 예전에는 40칸 격자에서 카드를 누르는 것이
  곧 **되돌릴 수 없는 지출의 시작**이었다. 지출은 오른쪽 발의 [영입한다] 하나로
  모였고, 그래서 카드에는 **`disabled` 가 없다** — 잠긴 것도 보유한 것도 눌러서
  오른쪽에서 읽을 수 있어야 한다 ("무엇을 향해 가는가"가 거기 있다).
- **못 사는 이유는 문장으로 말한다** (`canRecruit` 의 `reason` 그대로):
  이미 보유 · 스테이지 잠김(목표와 현재 진행도) · 골드 부족(모자란 액수와 잔액).
  흐린 버튼만 두면 플레이어는 화면이 고장 났다고 읽는다.
- **확인 모달은 남는다.** 골드는 유일한 재화이고 영입은 환급이 없다.
- **홀드 툴팁(`useHoldTip`)은 걷어냈다.** 그것이 있던 이유("카드에 이름·등급·가격
  밖에 없어 무엇을 사는지 모른다")가 오른쪽 상세로 **상시** 해결됐다. 같은 사실을
  두 곳에서 말하면 갈라진다 — 실제로 툴팁만 가격을 말하고 카드는 "보유 중"이라
  말하던 시절이 있었다. 홀드가 사라지면서 탭 판정이 포인터 이벤트에서 `onClick` 으로
  돌아왔고, `disabled` 우회 사고의 **원인 자체**가 없어졌다. 훅은 전투 HUD·지휘관
  패널이 계속 쓴다.
- **선택이 없으면 첫 번째를 고른다.** 영입 직후에도 선택은 유지되고, 그 자리에서
  "보유 중"으로 바뀐다.
- 지키는 기계: `src/screens/recruitCard.test.js`.

### 4.3 편성 > 편성 — 좌 6칸 / 우 로스터, 반반 (2026-08-05)

```
┌──────────────────────┬──────────────────────────────┐
│ [1][2][3][4][5][6]   │ 보유 동료 50종               │ ← 슬롯은 고정
├──────────────────────┤ ┌──┬──┬──┬──┐                │
│ 편성 적합도 · 경고   │ │  │  │  │  │  (스크롤)      │
│      (스크롤)        │ ├──┼──┼──┼──┤                │
├──────────────────────┤ │  │  │  │  │                │
│ [자동 추천]          │ └──┴──┴──┴──┘                │ ← 발 고정
└──────────────────────┴──────────────────────────────┘
```

**§4.1 과 같은 클래스를 쓴다** (`.split` / `.splitPane` / `.detailScroll` / `.detailFoot`).
두 칸은 `flex: 1 1 0` + `min-width: 0` 으로 **정확히 반반**이다 (실측 915×412 에서
443.5px / 443.5px, 1280×720 에서 620 / 620).

- **슬롯 6칸은 스크롤하지 않는다.** 고르는 쪽(로스터)이 흐르는 동안 놓는 쪽이
  화면에 남아 있어야 "이 칸에 저것을 넣는다"가 성립한다.
- `.slots` 의 트랙은 `repeat(6, minmax(0, 1fr))` 다. `1fr` 의 최소 폭은 `auto` 라
  **긴 이름 하나가 6칸 전체를 밀어낸다** — 바깥의 `min-width: 0` 만으로는 못 막는다.
- **드래그 재정렬**(`touch-action: none`)은 슬롯이 스크롤 컨테이너 **밖**에 있어
  세로 스크롤과 충돌하지 않는다. 슬롯을 스크롤 안으로 넣으면 그때부터 충돌한다.

> ★ **지휘관은 이 화면에 없다.** 위쪽 `[편성] [지휘관]` 탭 중 지휘관 쪽이 유일한
> 자리다 — 레벨·장구·주문은 동료 6칸과 **다른 층위**이고, 여기 두면 편성 화면이
> 세로로 길어져 정작 6칸을 고르는 일이 밀려난다.
> `src/screens/loadoutPanes.test.js` 가 되돌아오는 것을 막는다.

### 4.4 출격 > 초기 포커스 (2026-08-05)

**골라져 있는 스테이지는 언제나 하나이고, 그것은 "다음 도전"이다.**

초기값을 각자 정하면 갈라진다 — 실제로 선택은 `stages[0]`(항상 1-1), 보고 있는
월드는 `nextStageId()` 기준이라 **두 곳이 동시에 강조된 것처럼** 보였다.
둘 다 `nextStageId` 하나에서 나온다.

- 화면이 열릴 때와 **월드를 바꿀 때** 그 카드로 스크롤을 맞춘다. 고른 카드가
  스크롤 밖에 있으면 "아무것도 안 골라져 있다"와 화면상 같다.
- **사용자가 직접 카드를 고를 때는 맞추지 않는다.** 누를 때마다 목록이 튀는 것이
  더 성가시다.

## 6. 접근성

| 항목 | 대응 | 구현 (P7-15) |
|---|---|---|
| 색맹 | 데미지 타입을 색 + **형태/글자** 동시 구분. 적 태그도 동일 | 적 태그는 상시 형태 아이콘(`EnemyBadges`). 색약 모드를 켜면 데미지 숫자에 속성 표기(`물`·`술`·`신`)가 붙는다 |
| 저시력 | UI 스케일 3단계 (100% / 115% / 130%) | `#ui-overlay` 의 `zoom` — **터치 타깃도 같이 커진다** |
| 청각 | 모든 중요 이벤트에 시각 피드백 병행 | BGM·SFX 개별 음량 + 음소거 |
| 운동 | **자동 위치 모드 + 원터치 소환 + 오토 배틀** 조합으로 최소 조작 플레이 가능 | 자동 지휘 + 원터치 소환 + 자동 진행 속도(1/1.5/2배) |
| 전정 | 화면 흔들림 · 히트스톱 개별 끄기 | 둘 다 연출 계층만 바꾼다 — **밸런스와 결정론에 영향이 없다** |
| 진동 | 켜기/끄기. 기본 ON (`@capacitor/haptics`) | 설정 > 접근성 |
| 텍스트 | 시스템 폰트 옵션 제공 (픽셀 폰트 가독성 문제 시) | 미구현 — 긴 설명문은 `.body-text` 로 이미 시스템 폰트다 |

> **설정 화면 자체도 이 규칙을 지킨다.** 세그먼트 버튼의 선택 상태를 색만으로 표시하면
> 색약 사용자에게는 아무 표시가 없는 것과 같다. 테두리 강조 + 표식을 함께 쓴다.
> 켜기/끄기 토글도 색이 아니라 **글자**로 상태를 말한다.
