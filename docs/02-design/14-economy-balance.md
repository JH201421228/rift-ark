## 2. 스케일링 수식

### 2.1 적 HP — 구간별 감쇠 (안티월 핵심)

```
HP(s) = HP_base × 1.110^s                     (1  ≤ s ≤ 30)
HP(s) = HP(30)  × 1.075^(s-30)                (31 ≤ s ≤ 80)
HP(s) = HP(80)  × 1.055^(s-80)                (81 ≤ s ≤ 200)

HP_base = 40
보스 스테이지(10 배수): × 1.4
하드 모드:              HP × 1.35 · ATK × 1.35 · 스폰 수 × 1.15
나이트메어:             × 1.9 + 신규 메커니즘 (미구현)
```

> **구현 (P6-10).** 난이도 배율은 `balance.json:difficulty.levels.*` 가 소유하고
> `src/game/logic/difficulty.js` 가 규칙을 갖는다. 설계 원안의 "태그 1개 추가"는
> 넣지 않았다 — 전 적에게 태그를 붙이면 상성 답이 스테이지 단위로 고정되어
> "한 편성 안에 서로 다른 답을 넣는다"(보스 페이즈 P6-05)와 정반대로 작동한다.
> 대신 **스폰 수**를 세 번째 손잡이로 썼다: HP·ATK 만 올리면 하드가 '더 오래
> 때리기'가 되지만, 동시 처리 수가 늘면 광역 화력과 방벽 용량이 실제로 시험된다.
> 실측은 `docs/04-plan/33-execution-plan.md` P6-10 구현 노트 참조.

**샘플 값**

| 스테이지 | 잡몹 HP | 비고 |
|---|---|---|
| 1 | 44 | |
| 10 | 114 | 보스 ×1.4 = 159 |
| 30 | 917 | 감쇠 1차 전환점 |
| 50 | 3,919 | |
| 80 | 34,167 | 감쇠 2차 전환점 |
| 120 | 294,000 | |
| 200 | 21,300,000 | |

> **감쇠 없이 1.11을 200스테이지까지 유지하면 HP가 약 5.8 × 10¹⁰ 이 된다.** 플레이어 파워는 업그레이드 비용 상승 때문에 그 속도로 성장할 수 없으므로 격차가 무한히 벌어진다. 이것이 이 장르가 스테이지 30–50에서 플레이어를 잃는 수학적 이유다.

### 2.2 적 ATK / breachDamage

```
ATK(s)  = 6 × 1.085^s   (구간 감쇠는 HP와 동일 지점에서 1.06 / 1.045로)
breach(s) = clamp(2 + floor(s / 12), 2, 12)
엘리트 breach = breach × 2.5
```

ATK 성장이 HP보다 완만한 이유: **플레이어의 좌절은 "못 죽인다"보다 "순식간에 뚫린다"에서 더 크게 온다.** 방어보다 화력 요구를 먼저 올린다.

### 2.3 플레이어 파워

```
Unit_ATK(lvl)  = base_ATK × 1.055^lvl
Unit_HP(lvl)   = base_HP  × 1.060^lvl
Level_cost(lvl)= 60 × 1.120^lvl          (골드)

Rank_mult      = [1.0, 1.35, 1.85, 2.50, 3.40]
Gear_mult      = [1.0, 1.15, 1.35, 1.60]   × (1 + 0.03 × 강화수치)
Meta_tree_mult = 1.0 → 최대 2.2 (별 트리 완주)
소유효과_mult  = 1.0 → 최대 1.25 (역할별 상한)

총 파워 = base × Lv × Rank × Gear × Meta × Owned
```

### 2.4 파워 vs 난이도 정합

핵심 관계:
```
연속 성장 (레벨 1.055^lvl)  <  적 성장 (1.11 → 1.075 → 1.055)
격차는 이산 계단이 메운다:
  랭크업        ×1.35 단위 점프  (10스테이지마다 1회 가능하도록 파편 수급 설계)
  장비 티어업   ×1.15 단위 점프  (20스테이지마다)
  신규 동료 해금 편성 질 향상    (5스테이지마다 1종)
  별 트리       ×1.02~1.05 누적
```

> **감사 규칙:** 시뮬레이터는 매 10스테이지 구간마다 **"그 시점에 무과금으로 도달 가능한 최대 파워"** 를 계산하고, 해당 구간 최종 스테이지의 승률이 **55% 이상**인지 검증한다. 미달 시 빌드 실패.

## 3. 전투 내 자원

### 3.1 마나 곡선

```
regen(t)       = 6.0                (t < tempo_shift)
               = 12.0               (t ≥ tempo_shift)
tempo_shift    = 전체 웨이브의 60% 지점
start_mana     = 60
max_mana       = 200 (기록보관소로 300)
kill_refund    = floor(enemy_cost × 0.15)
```

**90초 전투의 총 마나 예산**
```
1막 (54초, regen 6.0):  60 + 324 = 384
2막 (36초, regen 12.0): 432
처치 환급 (평균):        ~180
합계:                    ~996 마나
```
→ 평균 코스트 30 기준 **약 33회 소환**. 코스트 상승을 감안하면 실질 **22–26회**. 이것이 "충분히 바쁘되 압도되지 않는" 목표 밀도다.

### 3.2 소환 코스트 상승 검증

```
cost(type, n) = base × 1.18^n,  12초마다 n -= 1
```

| 연속 소환 | 배율 | 코스트 30 유닛 |
|---|---|---|
| 1회차 | 1.00 | 30 |
| 2회차 | 1.18 | 35 |
| 3회차 | 1.39 | 42 |
| 4회차 | 1.64 | 49 |
| 5회차 | 1.94 | 58 |
| 6회차 | 2.29 | 69 |

**검증 기준:** 시뮬레이터에서 **단일 유닛 스팸 편성의 승률이 다양화 편성보다 항상 낮을 것.** 이 조건이 깨지면 1.18을 상향한다.

## 4. 젬 경제

### 4.1 가격 정책

| 항목 | 값 |
|---|---|
| 1회 뽑기 | **150 젬** |
| 10연 | **1,500 젬** (10회분, 할인 없음 — **레어 이상 확정**이 할인 대신) |
| 던전 리필 | 50 / 100 / 150 젬 (누진, **던전마다** 일 3회 한도 = 최대 9회 · 900젬/일) |
| 각인 리롤 추가 | 30 젬 |
| 시간 단축 | 10분당 5젬 |

> **던전 리필은 던전마다 따로 센다** (`dungeons.js:buyGemEntry` 가 `runOf(state, dungeonId)` 기준).
> 던전이 3종이므로 하루 최대 9회 · 900젬이고, 이것이 무과금 일일 젬(≈220)의 4배가 넘는
> 최대 소모처다. 단일 출처는 `src/game/data/dungeons.json:entries` 이며 이 표는 그 사본이다 —
> 값을 고칠 때는 데이터를 먼저 고치고 여기로 옮겨 적는다 (절대규칙 10).
>
> **환율 주의:** `gemCost` 는 티어와 무관한 고정값인데 금고 보상은 T1 3,700 → T5 2,100,000
> (×567)이다. 상점 `gold_pouch_s`(젬 100 → 골드 20,000)의 환율은 200 골드/젬 고정이므로,
> T1 74 골드/젬 · T3 1,440 · T5 42,000 으로 벌어진다 — 스테이지 40 부터 상점 골드 상품은
> 아무도 사지 않는 죽은 SKU 다. 같은 거래에 두 개의 가격이 있는 상태이며, 환율 출처를
> 하나로 모으는 것은 별도 티켓이다 (P8, 수치 변경이라 밸런스 재검증이 필요하다).

### 4.2 무과금 젬 수급

| 출처 | 일일 평균 |
|---|---|
| 일일 로그인 | 20 |
| 일일 퀘스트 (3+1) | 40 |
| 주간 퀘스트 (환산) | 25 |
| 캠페인 진행 보상 (환산) | 60 |
| 별 트리 / 업적 (환산) | 35 |
| 이벤트 (환산) | 40 |
| **합계** | **≈ 220 / 일** |

→ **약 6.8일에 10연 1회.** 목표(5–7일)에 부합.

**배틀패스 무료 트랙**은 여기에 시즌당 약 900젬을 추가한다 (≈ +32/일).

### 4.3 인플레이션 통제

- **방치 누적 상한 8h** — 주 단위 사재기 차단
- **최상위 배수구 개방형**: 장비 강화가 +15 이후에도 무한 계속되며 수익 감소 (후반 골드 무한 흡수)
- **이벤트 재화는 항상 만료** (시즌 종료 +7일)
- **보상 지급은 재화가 아니라 아이템으로.** 재화 보상이 라이브 게임 경제 붕괴 최다 원인
- **주간 수도꼭지/배수구 감사**: DAU 세그먼트별 골드 생성 대 소멸. **비율 1.15 초과가 2주 연속이면 콘텐츠보다 배수구를 먼저 추가**

**실효 확률** (소프트 천장 포함 시뮬레이션): L 1개당 평균 **약 38뽑**.

### 5.2 준수 요건

1. **게임 내 배너 화면에서 2탭 이내**에 위 테이블 전문 도달 가능
2. **공식 홈페이지 + 광고물**에도 동일 표기
3. **천장 조건 전문 공개** (한국법은 천장 시스템 공개도 의무)
4. **구매 전 표시** (Apple 3.1.1, Google Play 정책)
5. **서버 사이드 롤 로깅**: `{userId, timestamp, bannerId, tableVersion, seed, pityCounter, result[]}` — 법정 보존 기간 유지. 입증책임이 사업자에게 전환됐으므로 **임의의 개별 뽑기를 재구성할 수 없으면 방어 불가**
6. **출시 후 확률·천장을 절대 하향 변경하지 않는다**

### 5.3 확률형은 가챠 하나뿐

**강화·합성·장비 옵션에 랜덤을 두지 않는다.**
- 랭크업: 파편 N개 → 100% 성공
- 장비 강화: 100% 성공, 비용만 상승
- 장비 옵션: 고정

→ **캡슐형 1종만 규제 대응하면 되므로 컴플라이언스 비용과 리스크가 최소화된다.** (`01-research/02` §3.5)

## 6. 스테이지 30–50 벽 방지 — 6중 방어

| # | 방어 | 구현 |
|---|---|---|
| 1 | **지수 감쇠** | §2.1 |
| 2 | **계단 가용성 보장** | 시뮬레이터가 10스테이지 구간마다 무과금 도달 파워로 승률 ≥55% 검증 |
| 3 | **진행 트랙 분기** | 스테이지 25에서 자원 던전·기억의 탑 해금. 막히면 우회 |
| 4 | **무한 모드** | 기억의 탑 = 무한 헤드룸 |
| 5 | **오토/방치** | 스테이지 20부터. "막혔다" → "쌓이고 있다" |
| 6 | **동적 보조** | 동일 스테이지 **5연속 실패** 시 1회성 "불굴의 축복"(전 능력치 +15%, 해당 스테이지 한정). **난이도 하향이 아니라 끈기 보상으로 프레이밍** |

**자동 벽 탐지:** 텔레메트리에서 **첫 시도 승률 < 25%** 또는 **평균 시도 > 4회** 인 스테이지는 대시보드에 자동 플래그.

| B15 | 경제 정합 | 시뮬 100스테이지 진행 시 획득 골드가 필요 업그레이드 비용의 **1.05–1.25배** |

**실패 시 빌드 차단.** B1, B4, B6, B7은 하드 게이트다.

## 8. 튜닝 워크플로

```
1. 기획자가 FE/src/game/data/*.json 수정
2. npm run balance          → 헤드리스 시뮬 500시드 × 전 스테이지
3. balance-report.csv 생성  → 승률/전투길이/편성분포
4. npm run balance:check    → §7 코퍼스 검증, 실패 시 exit 1
5. 통과하면 커밋
```

**엔지니어 개입 없이 기획자가 이 사이클을 돌 수 있어야 한다.** 이것이 라이브옵스 케이던스(월 8–15 이벤트)를 가능하게 하는 전제 조건이다.
