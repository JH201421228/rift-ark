## ★ 0. 방침 — **게임 완성이 먼저다** (2026-08-03 전환)

이 로드맵은 원래 **소프트런칭 지표로 설계를 검증하는** 구조였다.
M1 게이트는 "팀 외부 5명에게 플레이시켜 묻는다"였고, M4 전체가 실지표 판정이었다.

**그 구조를 걷어낸다.** 이유는 하나다 — **지금 그것들은 진행을 막기만 한다.**
외부 테스터도, 실제 플레이어 데이터도, 스토어 계정도 없다. 없는 입력을 기다리는 게이트는
영원히 열리지 않는 게이트이고, 열리지 않는 게이트 뒤에서 개발이 멈춘다.

### 새 목표

> **혼자서 처음부터 끝까지 플레이할 수 있는, 완성된 게임 하나.**

검증은 **사람이 아니라 기계가** 한다. 게이트는 전부 이 저장소 안에서 재현 가능해야 한다:

| 걷어낸 게이트 | 대체 게이트 |
|---|---|
| 외부 5명 "한 판 더 하고 싶은가" | `npm run balance:check` 하드 게이트 · 프레임 예산 · 자동 플레이 완주 |
| D1/D7/D30 리텐션 판정 | **없음.** 실플레이어가 있어야 성립한다 — 판정 자체를 제거 |
| FTUE 완료율 (내부 테스트) | `logic/ftue.js` 순수 함수 테스트 + `guidedTapCount()` 예산 검증 |
| 크래시 프리 세션 99.5% | lint 0 · 테스트 전항 통과 · `vite build` 성공 · 씬 `shutdown()` 검사 |
| 결제 전환 · 수익화 A/B | 결제는 **목(mock)** 으로 완결. 실 SDK 는 어댑터 경계까지만 |

### 완성 이후 (이 문서의 범위 밖)

**게임이 완성되면 사용자가 직접 플레이하며 하나씩 고친다.** 그때 나오는 것이
이 프로젝트의 진짜 첫 피드백이다. 아래는 그 이후로 미룬다 — 삭제가 아니라 **연기**다:

- 소프트런칭 · 지표 판정 · UA
- 실 광고 SDK · 실 분석 SDK · 실 결제 (전부 어댑터만 만들어 둔다)
- PvP · 길드 · 리더보드 (서버가 없으므로 비동기 고스트 방식이라도 설계 재검토가 필요하다)
- 원격 설정 · 라이브옵스 캘린더 · 현지화 · 스토어 자산
