# `PrivacyInfo.xcprivacy` — 왜 이 내용인가

> 이 파일은 **Xcode 타깃에 들어 있지 않다.** 번들에 복사되지 않으므로 앱 크기에
> 영향이 없고, 심사 대상도 아니다. `PrivacyInfo.xcprivacy` 자체에는
> **주석을 한 글자도 넣지 않는다** — 이유는 아래 §3.

관련 문서: [`docs/06-release/51-app-store-paid-codemagic.md`](../../../../docs/06-release/51-app-store-paid-codemagic.md) §5.3.2

---

## 1. 이 파일이 IPA 에 없던 4일 (2026-08-06 ~ 08-10)

`PrivacyInfo.xcprivacy` 는 2026-08-08 에 만들어졌지만 `App.xcodeproj/project.pbxproj`
에 참조가 없어 **IPA 에 들어가지 않았다.** 빌드는 성공했고 CI 는 아무 경고도 내지
않았다. 유일한 신호는 업로드 며칠 뒤 오는 `ITMS-91053` 메일이었다.

> ★★★ **번들에 없던 파일은 옳은지 그른지조차 알 수 없다.** "만들어 뒀다"는 검증이
> 아니다. 타깃에 넣은 2026-08-10 에 **처음으로 검증을 받고 그 자리에서 떨어졌다.**

`check:prod` 의 **A8** 이 이제 pbxproj 참조를 강제한다.

## 2. `NSPrivacyTracking` 은 왜 `false` 인가

**이 파일은 "우리 앱 자신의 코드"를 기술한다.** 이 게임의 1차 코드는 네트워크를
하나도 타지 않는다 — 계정도 서버도 없고 세이브는 기기 안에만 있다.

추적을 하는 것은 **Google Mobile Ads SDK** 이고, 그 SDK 는
`GoogleMobileAds.xcframework` 안에 **자기 몫의 `PrivacyInfo.xcprivacy` 를 내장**한다
(v11.2.0+). Xcode 가 빌드 시 그것들을 이 파일과 **자동으로 병합**해 하나의
Privacy Report 를 만든다. SDK 의 추적과 도메인을 **우리가 대신 적을 필요가 없다.**

### ⛔ 도메인을 채워서 통과시키지 않는다

2026-08-10 에 `NSPrivacyTracking = true` + 빈 `NSPrivacyTrackingDomains` 로
`ITMS-91056` 을 맞았다. 고치는 방향이 둘인데 **한쪽은 위험하다.**

| 안 | 결과 |
|---|---|
| ① 도메인에 구글 광고 도메인을 적는다 | ⛔ **광고가 깨진다** |
| ② `NSPrivacyTracking = false` · 도메인 비움 | ✅ 택함 |

**①이 위험한 이유: 이 키는 선언이 아니라 동작이다.** 여기 적힌 도메인은
**ATT 를 허용하지 않은 사용자에게 네트워크 요청이 실패한다.** 구글 광고 도메인을
적으면 ATT 거부 사용자에게 **비개인화 광고까지 막히고**, 개인정보 처리방침의
*"거부해도 광고는 계속 표시됩니다"* 가 그 자리에서 거짓이 된다.

### App Privacy 의 "Used to Track You = 예" 와 모순되지 않는다

둘은 다른 것을 묻는다:

| | 무엇을 묻는가 | 답 |
|---|---|---|
| App Store Connect 설문 | **앱 전체** (서드파티 SDK 포함) | **예** |
| 이 매니페스트 | **우리 코드** | 아니오 (SDK 가 자기 것을 선언) |

Apple 이 병합을 설계해 둔 이유가 그것이다. **한쪽에 맞추려고 다른 쪽을 거짓으로
적지 않는다.**

`NSPrivacyCollectedDataTypes` 를 비운 것도 같은 이유다 — 광고 식별자를 수집하는
것은 SDK 다. `NSPrivacyTracking` 이 false 인데 수집 항목에 `Tracking = true` 를
남기면 그 자체로 모순이다.

## 3. ★★★ 주석을 넣지 않는다

**빌드 13 이 `NSPrivacyTracking = false` 로 고친 뒤에도 같은 `ITMS-91056` 으로
떨어졌다.** 구조는 정본과 완전히 같았고, 레퍼런스 예시들과 **다른 점이 하나
남아 있었다 — 803자짜리 한국어 XML 주석**이다.

주석을 걷어내자 파일이 4,366 바이트에서 **594 바이트**가 됐다. Apple 의 검증기가
표준 XML 파서를 쓴다면 주석은 무해하지만, **그것이 참이라는 근거가 우리에게 없다.**
그리고 이 파일에서 주석으로 얻는 것보다 **업로드가 막히는 비용이 압도적으로 크다.**

> 그래서 설명은 전부 이 `.md` 로 왔다. 저장소 규약은 "지식은 대상 옆에 둔다" 인데,
> **대상이 주석을 못 받는 파일이면 옆 파일이 그 자리다.**

`check:prod` 의 **A10** 이 주석과 낯선 최상위 키를 막는다.

## 4. 남긴 것 하나 — `UserDefaults` / `CA92.1`

`@capacitor/preferences` 가 게임 세이브·설정을 기기 내 `UserDefaults` 에 저장한다.
기기 밖으로 나가지 않으므로 "수집"은 아니지만, **Required Reason API 사용 사유**는
별개로 선언해야 한다. `CA92.1` 이 *"앱 자신의 데이터를 앱 자신의 UserDefaults 에
저장·접근"* 사유다.

## 5. 되돌릴 때

| 언제 | 무엇을 함께 바꾸는가 |
|---|---|
| ATT 를 끄기로 한다 | `docs/06-release/51-…md` §5.3.3 의 **넷**을 같은 커밋에서 (방침 · App Privacy · 이 파일 · Play 데이터 보안) |
| 광고 SDK 를 더 붙인다 | 그 SDK 가 자기 매니페스트를 내장하는지 확인한다. 없으면 **그때는** 우리가 적어야 한다 |
| 1차 코드가 네트워크를 타기 시작한다 | §2 의 전제가 깨진다. `NSPrivacyTracking` 부터 다시 판단한다 |
